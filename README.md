# RocoAgent — 洛克王国世界 PvP 自动对战系统

> 立项：2026-11-17
> 目标：打进人类排位前 50%
> 特点：分层架构，全流程可记录，支持自我优化

---

## 一、设计原则

```
① 感知与决策分离
   感知层只负责"把屏幕变成数字"，不掺任何判断
   决策层只吃结构化 state，不碰像素

② 每一回合都落盘
   state + action + 结果 → logs/，这是自优化的唯一原料

③ 决策可回放
   给定同一条日志，能重算出当时的决策，便于复盘

④ 出招不经过大模型
   实时回路全是本地代码，延迟 < 0.5 秒
   大模型只负责：写代码、定策略、复盘日志
```

## 二、分层架构

```
┌─────────────────────────────────────────┐
│  perception  截图 → state.json          │
│   我方：精灵/HP/能量/技能(已知)          │
│   敌方：精灵/HP%/属性/强化图标           │
│   场上：天气/印记/回合数                 │
└────────────────┬────────────────────────┘
                 ↓ state
┌─────────────────────────────────────────┐
│  policy  state → action                 │
│   规则层：能秒？会被秒？能量够？          │
│   计算层：伤害区间（含属性克制）          │
│   搜索层：2~3 回合的换人/出招推演        │
└────────────────┬────────────────────────┘
                 ↓ action
┌─────────────────────────────────────────┐
│  actuator  action → ESP32 按键           │
│   BLE 指令，硬件 HID，反作弊安全          │
└─────────────────────────────────────────┘
                 ↓
┌─────────────────────────────────────────┐
│  logger  每回合落盘 → logs/*.jsonl       │
└─────────────────────────────────────────┘
```

### 路径与环境变量

代码里不出现任何绝对路径，全部集中在 `src/paths.py`。仓库内的目录由
`paths.py` 自身位置推出，克隆到任何盘符都能直接跑：

| 文件 | 作用 |
|---|---|
| `paths.ROOT` | 仓库根 |
| `paths.DATA` / `paths.DB` | `data/` 与 `roco.sqlite3` |
| `paths.LOGS` | `logs/` |
| `paths.ASSETS` / `paths.CONFIG` / `paths.UI` | 其余目录 |

仓库外的东西（不在版本库里，需要自己准备）用环境变量指，或者写进
`config/paths.local.json`（不入库，样板见 `config/paths.example.json`）：

| 变量 | 说明 |
|---|---|
| `ROCO_TOOLS` | 外部工具目录：`esp_shim`、`digitread`、`winocr.ps1` |
| `ROCO_GAME_DATA` | 游戏原始解包数据 |
| `ROCO_RAW` | 图鉴原始 json |
| `ROCO_HELPER` | 第三方助手目录 |
| `ROCO_ROOT` / `ROCO_DATA_DIR` / `ROCO_LOGS` | 需要把数据放到别处时才设 |

```powershell
$env:ROCO_TOOLS = "<你的工具目录>"
python src\robot.py
```

## 三之二、前端（2026-11-21 新增）

三块独立页面，共用 `src/ui_server.py` 提供数据（只读日志，不写业务数据）。

```powershell
python src\ui.py                  # 服务 + 控制台
python src\ui.py --overlay        # 服务 + 悬浮窗（盖在游戏上）
python src\ui.py --serve-only     # 只提供数据
```

| 页面 | 用途 | 特点 |
|---|---|---|
| `ui/index.html` 悬浮窗 | 打架时看 | 320px 宽，可拖动/折叠，透明度 20~100%，点击穿透 |
| `ui/console.html` 控制台 | 开局前/收工后 | 启停机器人、实时日志、战绩、队伍、图鉴、回合明细 |
| `ui_server.py` | 数据源 | 零依赖 stdlib，`/api/bot` 90ms，JSONL 按 mtime 缓存 |

悬浮窗的设计约束（都是实测出来的）：

```
· 半透明深色面板压在亮背景上会变亮，白字对比度掉到 1.59:1
  -> 所有文字加 1px 暗色描边，同样透明度下回到 10.65:1
· 图形元素（血条底槽/边框）没有描边，20% 透明度时会消失
  -> 给它们不透明度下限补偿
· backdrop-filter 在悬浮窗上无效（采不到背后像素）
  -> 用实心半透明 + 噪点 + 顶部高光
· pywebview 的透明是延迟生效的，且窗口没有 WS_EX_LAYERED
  -> 等页面画出来 -> ShowWindow(0/5) 一次 -> 自己加标志
```

详细设计、数据契约、踩坑记录见 `docs/FRONTEND.md`。

## 五、自优化机制

```
第一层  规则参数可调
        例如「残血换人阈值」「能量保留阈值」
        用日志回放做网格搜索，找胜率最高的参数组

第二层  对局统计
        每个决策点记录：局面特征 → 选择 → 结果
        统计「哪种选择在同类局面下胜率高」

第三层  （后期）小模型
        用日志训练一个分类器，替代规则打分
        输入 state 向量，输出 4+2 个动作的概率
```

## 六之二、战斗模拟器（2026-11-23，S8-S22）

```

  血脉系统        血脉门控 / 愿力冲击（18 系）/ 愿力强化
  共鸣魔法        愿力强化 / 光合治愈 / 闪焰爆发 / 节流术
  进化之力        首领化（形态映射 + 特性切换 + 每场 1 次）
  特性原语        35 个 handler（应对变身/自动脱离/槽位锁/
                  开场技能改写/HP 阈值条件/…）
  效果解析        4 层：手写 > authority > link > 无
  应对效果引擎    153 技效果子句（9 个 ctx 原语）
实战校准（S18-S20）
  公式验证        卡牌预览比值聚集 1.0/1.25/2.0/4.0 ✅
  per-foe 校准    出伤 k（21 对手，残差中位 0%）
                  承伤 k_in（38 对手，残差 19% vs 未校准 51%）
  已接进决策      policy_v2 的 dmg ×k、_incoming ×k_in
UI（S17/S21）    手操窗口：魔法/进化按钮 + 血脉徽章 + 条件指示
```
