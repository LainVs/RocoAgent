# RocoAgent 系统设计

> 目标：一个**可解释、可验证、可持续改进**的 PvP 代打系统。
> 约束：游戏只认 BLE 硬件输入；状态只能靠截图感知；伤害是确定性的（无暴击/无 miss/全公开）。

---

## 一、设计原则

| 原则 | 含义 |
|---|---|
| **先能观测，再谈决策** | 读数不准时，任何算法都是在放大噪声 |
| **语义判据优先于坐标** | 用"种族名/词表/指纹"判定，不写死像素坐标 |
| **每一条结论都要能证伪** | 公式必须用真实数据回归；残差不为 0 就是缺项 |
| **任何自动化都要有兜底** | 超时、卡死、丢焦点，都必须能自恢复 |
| **决策可回放** | 每个动作都要留下"当时看到什么" |

## 二、分层

```
┌─────────────────────────────────────────────────────┐
│ L5 学习层   模拟器自对弈 / 离线复盘 / 队伍与配招优化      │  sim.py+NRC_
├─────────────────────────────────────────────────────┤
│ L4 决策层   minimax + 每节点 LP（同时出招）              │  policy_v3
├─────────────────────────────────────────────────────┤
│ L3 模型层   面板/伤害/魔力/等级衰减/对位库               │  dmg_calc, lives,
│                                                      │  pet_state, matchup_db
├─────────────────────────────────────────────────────┤
│ L2 状态层   把画面变成一个结构化 state                   │  robot.Perc + hud
├─────────────────────────────────────────────────────┤
│ L1 感知层   截图、头像匹配、OCR、模板                    │  Screen, portraits,
│                                                      │  ocr_cn, digitread
├─────────────────────────────────────────────────────┤
│ L0 执行层   BLE 硬件输入 + 焦点守卫                      │  esp_shim, espfast
└─────────────────────────────────────────────────────┘
```

**依赖方向：上层依赖下层，下层不知道上层存在。**
决策层不允许直接抓屏，感知层不允许做决策。

---

## 三、核心数据契约

每回合产出一个 `state`，所有层都吃它：

```python
state = {
  "t": 1234.5,
  "battle": True,              # 是否在战斗中
  "bar": True,                 # 技能栏是否可读
  "countdown": True,           # 是否我的决策窗口
  "my_pct": 64.2, "foe_pct": 51.0,
  "energy": (7, 10),           # 我方能量（L2 补）
  "skills": [                  # 四张卡
    {"index":1, "value":162, "color":"green",
     "lit":True, "plate":245, "kind":"num"},
    ...
  ],
  "my_pet": "恶魔狼",           # 种族名（头像反查）
  "foe_pet": "龙息帕尔",
  "foe_cast": "付给恶魔的赎价",  # 对面本回合技能（L2 补）
  "lives": {"me": 3, "foe": 4}, # 魔力
  "turn": 7,
}
```

**契约的两条铁律**：

1. 读不到就写 `None`，**绝不填默认值**（默认值会被当成真值参与计算）
2. 每个字段必须能追溯到"哪个区域、用什么方法读的"

## 四、模块清单

### L0 执行
| 文件 | 职责 |
|---|---|
| `espfast.py` | BLE 常连守护进程（TCP 9998），唯一持有板子 |
| `esp_shim.py` | 给机器人用的同步接口（click_at / key） |
| `robot.click_abs()` | 点击前的双重守卫：客户区内 + 目标确实是游戏窗口 |

### L1 感知
| 文件 | 职责 |
|---|---|
| `robot.Screen` | 截图（窗口/客户区两种坐标系 + 分辨率自适应 `sbox`） |
| `portraits.py` | 头像模板匹配（我方/对面两套库，带领先优势判定） |
| `ocr_cn.py` | RapidOCR + 封闭词表最近邻 |
| `digitread.py` | 卡面伤害数字切分与模板识别 |
| `hud.py` | 能量 `★N/10`、技能播报 |

### L2 状态
| 文件 | 职责 |
|---|---|
| `robot.Perc.observe()` | 每次轮询产出 state（~25ms） |
| `robot._check_active_pet/_check_foe` | 双方身份（头像 → 种族名） |
| `foe_panel.py` | 未知对手点开特性面板补录（名字/特性/技能） |

### L3 模型
| 文件 | 职责 |
|---|---|
| `gamedb.py` → `roco.sqlite3` | 精灵/技能/特性/克制/学习表 |
| `dmg_calc.py` | 伤害公式（已验证零误差） |
| `lives.py` | 魔力结算（叠加规则） |
| `pet_state.py` | 等级衰减（冥古龙） |
| `matchup_db.py` | 对位统计（谁打谁多少） |

### L4 决策
| 文件 | 职责 |
|---|---|
| `robot.decide()` | 当前策略：最大可用伤害 + 治疗/撤退/聚能 |
| `policy_v2.py` | 期望值策略（TKO/TTD），影子运行 |
| `policy_v3.py`(待) | minimax + LP |

### L5 学习
| 文件 | 职责 |
|---|---|
| `sim.py` | 确定性模拟器（面板/伤害/先手） |
| `NRC_AI`（外部） | 完整战斗引擎（效果/印记/回合流程） |
| `label_portraits.py` / `cleanup_portraits.py` | 头像库自动生长 |

### 运维
| 文件 | 职责 |
|---|---|
| `watchdog.py` | 计划任务每 2 分钟巡检：拉起 espfast/机器人/监控 |
| `monitor.py` | 每 30s 存一张画面 |
| `capture.py --watch-result` | 结算页连拍 |
| `roco_gui.py` | 原生管理面板（日志/战绩/回合/队伍/头像标注） |
| `record.py` | 读「历史战绩 胜利/失败」→ 权威胜负 |

## 五、一回合的生命周期

```
① Screen.grab ──────────────→ 四个区域（血条/技能栏/头像/能量）
② Perc.observe ─────────────→ state
③ 身份识别 ─────────────────→ my_pet / foe_pet（未知则触发面板补录）
④ 决策（decide / policy）────→ (action, why)
⑤ 动作前守卫 ───────────────→ 客户区内？窗口属于游戏？卡是亮的？
⑥ BLE 发送 ─────────────────→ 按键/点击
⑦ 记录 ─────────────────────→ turns.jsonl + 动作截图 + 卡面快照
⑧ 回合后校验 ───────────────→ 血量变化？没变化则本回合无效
```

**关键设计**：第 ⑤ 步是**唯一**的出口。所有动作必须过它，
这样"乱点"在结构上就不可能发生。

## 六、关键接口

```python
# 感知
state = bot.observe()                    # L1→L2

# 决策
action, why = policy.decide(state, ctx)  # L3+L4
# action: ("skill", n) | ("energy",) | ("switch", slot)

# 动作
ok = bot.act(action)                     # 过守卫 → BLE → 记录

# 模拟（离线）
battle = sim.Battle(my_team, foe_team)
battle.step(my_action, foe_action)       # 确定性：同样输入同样输出
value = battle.evaluate()
```

**`sim.Battle.step()` 是全系统的收敛点**：
决策层用它做前瞻，学习层用它跑自对弈，验证层用它和真实对局对照。
**它准不准，决定整个系统的上限。**

## 七、失败模式与对策（都是踩过的坑）

| 失败 | 现象 | 对策 |
|---|---|---|
| 焦点丢失 | 所有按键被丢弃，机器人空转 | 点击前 `_raise_topmost`，连续失败则重试 |
| 窗口 rect 归零 | 点击坐标变成 -30000 | `_click_target_ok` 拒绝，等下一轮 |
| 结果页误判 | 一场被打断成好几场 | 需要 25s 无血条 + 检测段位卡 |
| 技能栏抖动 | 窗口计时被重置，一次不出手 | 2 秒迟滞，用倒计时驱动 |
| 聚能被打断 | 没蓝时按 F 白挨打 | 聚能前检查倒计时 + 对面是攻击型就换人 |
| 头像误认 | 把我方认成别的精灵 | 阈值 0.72 + 领先第二名 0.06 |

## 九、不做什么

```
✗ 不抓包（风险 > 收益，识别路径已够用）
✗ 不让 LLM 直接做决策（算不了伤害）
✗ 不在数据不干净时上复杂算法
✗ 不做浏览器 UI（性能）
```

## 十、一句话总结

> **感知决定下限，模型决定上限，决策只是把两者接起来。**
> 我们花在识别和公式上的时间，都是在抬高下限 —— 那是唯一不会返工的部分。
