# PvP 大数据：对面血量 / 防御 / 技能携带的概率分布

> 代码：`src/pvp_meta.py`　测试：`src/test_pvp_meta.py`
> 目标：把"对面大概多少血"从**一个区间**升级成**一个概率分布**，
> 从而回答用户要的那个问题：*我们这一下打掉对面百分之多少血的概率是多少*。

---

## 1. 为什么需要它

`foe_hp.hp_band()` 只能给 `(中性, +HP性格)` 两个端点：

```
音速犬  hp_band = (366, 419)
```

但真实排位里配法是有权重的。同一只寂灭骨龙：

```
固执 49% / 平和 31% / 慎重 6% / 悠闲 6% / 孤僻 3% / 大胆 3%
```

- `平和` 是 +HP 性格 → 490 血
- 其余大多是中性 → 425 血

所以"213 伤害能打掉多少"不是 43.5% 也不是 50.1%，而是：

```
425 血 (65.7%) -> 50.1%
490 血 (34.3%) -> 43.5%
```

`pct_at_least(213, 50%) = 0.657` —— 这一下能打掉一半血的概率是 65.7%。

## 2. 数据源

| 文件 | 内容 | 规模 |
|---|---|---|
| `data/external/rocom-data/data/lineups.json` | 真实 PvP 阵容（性格 / 四技能 / 推荐个体） | **169 套 / 1014 只** |
| `data/external/rocoarena/teams.json` | 天梯样本（含技能池 / 推荐性格） | 15 套 |
| `data/roco.sqlite3` `species` | 种族值 | 1228 只 |
| `config/nature_table.json` | 性格 → 六项倍率 | 31 种 |

覆盖情况（实测）：

- 物种：1014 只里 **996 只**能在数据库里查到（98.2%），
  6 只差在名字带「（首领形态）」后缀，`pvp_meta` 会自动去掉括号再查。
- 技能：373 个唯一技能，**只有 8 个不在数据库**（0.3%）。

## 3. 个体值（IV）的处理：只让性格产生分布

`statmodel.IV_PVP = 60`，PvP 是**点满一档**的，六项都用 60。
`my_team` 里 5 只精灵的 30 个实测面板值已经验证过这个模型（30/30 全中，
见 `docs/ARCHITECTURE.md`）。

所以：

```
HP    = calc_real_stat(种族hp, 60, 性格倍率.hp, is_hp=True)
物防  = calc_real_stat(种族def, 60, 性格倍率.pdef, is_hp=False)
```

**不把 `talents` 当成 IV 来源** —— 那是"推荐投资哪三项"，不是实际个体值。

---

## 4. 性格表缺口（诚实标注）

`config/nature_table.json` 缺 10 个在真实阵容里出现过的性格：

```
保守 / 紧张 / 孤僻 / 认真 / 浮躁 / 淘气 / 狂妄 / 沉着 / 马虎 / 理智
```

处理方式：

- **影响 HP 的一个都没有** → HP 分布完全不受影响。
- 影响物防的只有 孤僻 / 淘气 / 紧张（合计约 5%）→ 补全前按 neutral 处理。
- `pvp_meta.unknown_nature_share(sp)` 暴露缺口比例，方便以后补。

宁可区间偏宽，**不编造倍率**。

## 5. API

```python
import pvp_meta as M

M.sample_size("寂灭骨龙")        # 35
M.nature_dist("寂灭骨龙")        # [("固执",0.49), ("平和",0.31), ...]
M.hp_dist("寂灭骨龙")            # [(425,0.657), (490,0.343)]
M.def_dist("寂灭骨龙")           # [(191,0.057), (207,0.886), (238,0.057)]
M.mdef_dist("寂灭骨龙")
M.carry_rates("寂灭骨龙", top=8) # [("隼鳞",0.91), ("偷袭",0.60), ...]
M.pct_dist("寂灭骨龙", 213)
# {"lo":43.5, "mid":50.1, "hi":50.1,
#  "buckets":[[43.5,0.343],[50.1,0.657]],
#  "hp_dist":[[425,0.657],[490,0.343]], "n":35}
M.pct_at_least("寂灭骨龙", 213, 50)   # 0.657
```

命令行自检：

```powershell
python src\pvp_meta.py --stats
python src\pvp_meta.py --species 音速犬 --dmg 175
```

## 6. 接进状态 / 前端

`live_state.foe_block` 新增（都有默认值，旧调用方不受影响）：

```
hp_dist      [[值, 概率], ...]   按值升序
def_dist     [[值, 概率], ...]
nature_dist  [[性格, 概率], ...] 按概率降序
sample_n     样本数（0 = 没数据，前端不要编造）
```

`live_state.skill_block` 新增：

```
pct_lo / pct_mid / pct_hi   伤害占比的 p10 / 中位 / p90
pct_kill                    这一下 >= 对面当前血量的概率
```

悬浮窗（`ui/app.js`）：

- 血量 / 物防：多个值时显示范围，`title` 里是完整分布；
- 性格：显示 top1 + 概率，`title` 里是完整分布；
- 新增「可能技能」一行（携带率 top6）；
- 技能占比显示 `38~49%`，`title` 里是斩杀概率。

`robot._publish_state`（机器人运行时）和 `standalone.build_state`
（独立计算器）两条链路都会填这些字段。

## 7. 已知限制

1. **样本量偏小**：头部物种 25~35 次出场，冷门物种可能只有 1~2 次。
   `sample_n` 会一起下发，前端可以据此决定要不要显示分布。
2. **性格表缺 10 个**（见第 4 节）。
3. **技能携带率的分母是"该物种出场次数"**，所以四项技能携带率之和
   约为 4.0，不是 1.0。
4. **改名精灵**：`pvp_meta` 按种族名统计。敌方身份来自
   `portrait_onnx` / 特性反查，不是 HUD 名字，所以改名不影响。
