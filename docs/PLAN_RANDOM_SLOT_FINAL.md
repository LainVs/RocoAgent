# 计划：随机技能位的正确处理（最终版）

## 语义（官方数据原文）

| 技能 | effect | 描述原文 |
|---|---|---|
| **借用** | 21320010 | 每回合随机变成**己方队伍中其他精灵**的技能。 |
| **取念** | 21320020 | 每回合随机变成**敌方任意精灵**的技能，且该技能能耗-2。 |
| **复写** | 21320030 | 每回合随机变成**自己未携带**的技能，且该技能能耗-2。 |

三者共同点：**"每回合随机"** —— 卡面显示的名字每个回合都可能变。

## 实测吻合

音速犬槽1 = 「借用」，不同时刻读到 8 种不同技能：

```
07:07 火焰切割   08:11 崩拳      08:34 反击拳
08:54 影袭      09:46 叠浪      09:58 主轴
10:08 岩脉崩毁   10:18 漫反射
```

同一次上场内稳定（09:46:39/55/58 都是「叠浪」），跨上场变化。

而「每回合」意味着理论上同一次上场跨回合也会变 —— 实测稳定可能是
因为那几个采样点恰好在同一回合内。

## 随机范围的决定（这是修法的关键）

按描述分别取范围：

| 技能 | 词表来源 | 规模 |
|---|---|---|
| 借用 | 我方队伍**全部技能**（含不在 my_team 的临时队员） | ~20-30 |
| 取念 | 敌方（无解，退化到全库） | 1045 |
| 复写 | 该精灵全部可学技能（`species_skills` ∪ `skillbanks`） | 40-60 |

**但实测「借用」随机到的 崩拳/反击拳/影袭/叠浪/漫反射 都不在 my_team
的 5 只精灵技能里** —— 因为用户实机换过队员（日志里出现过
`画间沉铁兽`/`棋绮后`/`武者鸡`/`棋帕督` 等不在 my_team 的精灵）。

所以「借用」的实际范围 = **场上 6 只当前队员的技能**，而 `my_team`
只是缓存、会过期。**不能只信 my_team。**

### 保守方案（推荐）：随机位用全库词表 + 高门槛

理由：
1. 范围无法可靠确定（my_team 会过期、敌方技能不可知）
2. `Ocr.match` 逐候选算分，全库不会稀释分数（已验证）
3. 门槛用 0.90（全库匹配，比 0.80 严）
4. **`_unique_near` 对随机位禁用** —— 全库下唯一性几乎不可能成立，
   留着只会增加误配风险

## 随机位必须特殊处理的四件事

1. **词表**：全库（跳过配置/可学池逻辑）
2. **门槛**：0.90（`BAND_MIN_CONF`），不用 0.80
3. **缓存**：**不能永久缓存**。`_BAND_LAST` 的 `_BAND_TTL=600s` 对随机位
   必须改成"每次上场/每回合失效"
4. **`session_moves`**：随机位写入要标 `source="band-random"`，
   且**不参与**配置过期判定（`note_team_stale`）

## 需要撤销/修正的既有改动

### `_ident_confirmed` 门禁（`ed58d07`）

基于错误诊断（把「叠浪」当成身份抖动的证据）。但**保留它无害**：
换人后 1~3 秒不读，代价极小。而且换人后随机技能确实会变，
延后一点读反而更稳。**保留，但更正注释里的理由。**

### 「配置 ∪ 可学池」并集（`c8b2b6f`）

对非随机位仍然正确（解决「扬沙」缺失）。**保留**。
随机位走全库分支，不经过并集。

## 实现

在 `read_band` 里：

```python
# 判断该槽位是不是随机技能位
_random = _is_random_slot(db, pet, slot)
if _random:
    vocab, tier = _all_vocab(db), "random-all"
else:
    vocab, tier = _band_vocab(db, pet)
```

`_is_random_slot(db, pet, slot)`：
- 查 `my_team` 该精灵该槽位的配置技能
- 名字 ∈ {借用, 取念, 复写} -> True
- 但 my_team 会过期，若配置里查不到该精灵也返回 False（走正常路径）

`_BAND_LAST` 缓存：随机位不缓存（或 TTL 设很短如 20s）。

## 验收

1. 音速犬槽1（借用）能读出当期随机技能，conf >= 0.90
2. 随机位不触发 `note_team_stale`
3. 非随机位行为不变（扬沙/诋毁等仍正常）
4. 测试覆盖：随机位识别、全库词表、不缓存

## 教训记录

连续三轮把**游戏机制**误判成**代码 bug**，根因是从未查过「借用」是什么
技能。以后遇到"同一位置读出多个不同值"，第一步应该是**查该位置配的是
什么技能/特性**，而不是先怀疑识别链路。
