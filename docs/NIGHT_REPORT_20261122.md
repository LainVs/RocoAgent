## 二、逐个 bug 与证据

### 1. 板子掉线就退出进程（`_ble` 的 `SystemExit(3)`）

```
00:00:35 BLE key 3 failed (board offline)
00:03:00 BLE offline x6 -> exiting so the supervisor restarts with a full scan
```

重启也是 `BLE waiting for board`，9 分钟连不上 —— 退出没换来恢复，
只把正在打的一场连同内部状态丢了。

现在：标记 `_board_offline_since`，主循环冻结决策 + 后台重连，
超过 20 秒允许 `allow_discover=True`。恢复后打印
`BOARD back online after Ns` 继续。

### 2. 遮挡检测从来没接进主循环

`winio.is_covered()` 早就写好了，只有 `standalone` 在用。
OpenCode 窗口压在游戏左半边时，抓屏抓到的是聊天界面，识别读垃圾，
但界面仍显示"战斗中 · 未知"。

- 主循环每帧检查，被遮挡就 `_raise_topmost()`，抬不起来就等；
- `is_covered()` 从"只看窗口中心点"改成 **3×5 网格采样** ——
  实测遮挡经常是"盖住左半边"，中心点仍是游戏。

### 3. VS 准备页被当成结算页 -> 点掉对局

`logs/stuck_000004.png` 证据：VS 页底部「取消准备」和结算页「退出」
在同一个 `RESULT_BTN` band 里。

```
VS 准备页   white=13824  -> has_exit_button=True（误判）
真结算页    white= 8372  -> True
真实战斗帧  white=    0  -> False
```

于是"脱困"变成了"取消对局"（0 actions）。修法：脱困条件加
`not has_vs_screen(screen)`。

### 4. 对局结束判据：试了三种，最后用技能栏

| 判据 | 结果 |
|---|---|
| `battle=False` 持续 25 秒 | 对面回合被当结束 -> **弃权判负** |
| 我方 HUD 消失 12 秒 | 4:3 下血条常读不到 -> **误伤正常对局** |
| 画面指纹静止 | 结算页角色有呼吸动画 -> **5 分钟不触发** |
| **技能栏 40 秒没画** | ✅ 一局里每个我方回合都会画一次 |

`_end_match()` 还会在 `match_started=None` 时写假的
`MATCH 0 END (0s, 0 actions)`，已修。

### 5. 结算页卡死：`advance` 闸门被自己的修复关掉了

收紧 `_end_match` 之后 `match_ended_at` 永远不被设置，
`_idle_tick` 里 `may_advance` 闸门永远关着 —— 排位结算页
（只剩「我方战况」+「今日获得」）点不动，实测卡 5 分钟。

修法三层：`_idle_tick` 无条件调用 + 画面静止 6 秒例外 +
20 秒不在战斗 + 静止 8 秒直接 `_end_match()`。

### 6. `advance` 无限点击

```
00:57:28 advance splash (click 12)
00:57:31 advance splash (click 1)     <- 配额被指纹重置了
```

结算页角色有动画，4x3 指纹一直在变，`advance_count` 每帧清零。
现在要求新指纹**连续 2 秒不变**才算翻页。

### 7. 技能栏判据写死像素 -> 4:3 下永远 `bar=False`

```python
if xs[-1] - xs[0] > 220:                  # 写死
ok = all(120 <= g <= 420 for g in gaps)   # 写死
```

实测 4:3 下 `gaps = [106, 192, 226]`，第一个 106 直接判死。
改成相对比例（x 跨度 `0.45×宽`、gaps `0.05~0.30×高`）。

**踩坑**：第一次改以为改好了，但编辑落到了 x 跨度那段，`gaps` 那行
没变。表现是"三个判据单独算都通过，函数却返回 False"。
最后用 `inspect.getsource()` 打真实源码才看到旧值还在。
**以后改判据必须用 `inspect.getsource()` 确认磁盘代码真变了。**

### 8. 大厅被误判成战斗 -> 在大厅里盲出招

```
FOE_BAR (2251,170,245,20) -> {'pct': 24.5, 'color': 'red', 'ui': False}
日志：battle=True bar=False me=59.0 foe=29.8
      T18 SKILL 2 (bar never drew, blind)
```

大厅的段位横幅压在 `FOE_BAR` 上；"限时试用系别 5天0小时"被当倒计时。
硬闸：`battle=True` 时每秒探一次 `has_start_button()`，有就清掉。

### 9. 4:3 下 `battle` 恒 False（根因）

```python
battle = bars and my["ui"] and foe["ui"]    # ui = 血条上下 2px 灰底板
```

2048x1536 下血条**没有**那两条灰底板。

**走过的弯路（重要，别重试）**：试过"读不到就按偏移上下搜索"，
结果**制造假数据** ——

```
live7.png（我方 0/417 已倒的真实战斗）-> 搜索读到 my=100%
```

场景里到处都有满足颜色条件的色块。也试过"成对搜索 + 两侧同偏移 solid"，
仍在 live6/live7 上给出互相矛盾的偏移（-48 / -32）。

**结论：不做运行时搜索。读不到就报读不到，绝不猜。**

实际修法：

1. `_read_bar` 新增 `solid`：真血条的填充**从最左列开始且连续**
   （实测战斗帧 cols 0..229，场景色块是零散分布）；
2. `battle` 的 HUD 证据改成 `ui or solid`；
3. **技能栏画着就直接判战斗**（技能栏只在"对局中 + 我方回合"出现）；
4. VS 准备页排除：两边都满血且都无灰底板 -> 不是战斗。

### 10. `_fit` 横向拉伸把头像糊掉（我方识别率 16%）

2048x1536 下 `scale=(0.8, 0.96)`，头像框 76x80 的物理尺寸是 61x77。
`_fit` 直接 `resize(img, (76, 80))` —— **横向 ×1.25**，把图糊掉。

```
修复前  best 0.409（认错）
修复后  best 0.765（正确，跨过 0.72 阈值）
```

### 11. 我方头像 margin 天然很小

同一只精灵有多个形态模板（`银月狼王#2` / `#7`），分数差常只有 0.02~0.05。
要求 `margin >= 0.06` 把正确识别（0.82）也挡掉了。
改成"分数 >= 0.80 时不要求 margin"（形态选错无害，
`_portrait_species()` 会归一到种族名）。

### 12. 单帧识别不稳 -> 多帧投票

HUD 头像有入场/待机动画，同一只精灵连续帧分数在 **0.34~0.82** 之间跳。
改成累计投票：

```python
votes[name] += max(0.0, sc - 0.45)
if max(votes.values()) >= 0.25: 采纳
```

真换精灵 / 新一局时清空投票历史。

### 13. 卡面读出 700 伤害还当必杀

```
T1 SKILL 2 (skill 2: 700 dmg, 0 taken, priority +5 [v2 0.5375])
```

对面雪影冰灵最大血 ≈400。`standalone` 早就有这道过滤，
**机器人链路一直漏着**。两处都加 `dmg > 对面最大血 * 1.2 -> 不可读`。

### 14. `_stuck_at` / `now` 未初始化导致连续崩溃

```
AttributeError: 'Bot' object has no attribute '_stuck_at'
UnboundLocalError: cannot access local variable 'now'
```

两次都是"给实例加新字段 / 往主循环插代码"时漏了初始化。
`test_imports` 查不出这种错误，只有真跑才会炸。
**教训：往主循环插代码前，先确认 `now` 在插入点之前已赋值。**

### 15. 我方头像阈值定错（0.72 永远达不到）

在战斗中连抓 9 帧、用全部模板打分，统计真实分布：

```
正确种族最高分   0.57 ~ 0.71   （中位 0.64）
错误种族最高分   0.37 ~ 0.48   （中位 0.42）
两者间隔        >= 0.18
```

9 帧全部**正确认出「银月狼王」**，但**没有一帧达到 0.72**。
原阈值等于"永远不认" —— 这是 `pet identity unknown` 的主因。

改成 0.55 后 9/9 全过，识别率 16% -> **75%**。

绕过的弯路：以为模板失效（重建模板后自匹配 1.000，但测历史帧仍 0.72）
-> 以为取景偏移（大区域搜最佳位置 abs=(55,45)，框是 (55,47)，只差 2px）
-> 以为缩放不对（多尺度最佳在 0.9~1.0，收益很小）
-> **真正的问题只是阈值**。

**教训：阈值必须分别统计"正确类"和"错误类"的分数区间来定，
不能凭直觉取一个"看起来严格"的数。**

### 16. `advance splash` 在战斗中点屏幕

04:40:15 state battle=False bar=False me=100.0 foe=100.0
04:40:30 advance splash (click 1)      <- 在战斗中点了屏幕

### 17. 打 9 手的一局被「脱困」点掉

```
05:13:48 FAINT -> dead_count=1
05:14:01 state battle=False bar=False me=None foe=None
05:14:24 STUCK on result screen (turn=9) -> click 退出
```

换人/力竭期间技能栏不画、血条读不到，`battle=False`；
而 `has_exit_button()` 只看白色连通域，**战斗画面底部那排按键也命中**。

两条判据（`STUCK on result screen` 和 `result screen (exit button)`）

### 18. FOE SCAN 0/136 成功，只是在战斗里点屏幕

整晚 1097 条 `FOE SCAN` 日志统计：

```
点击尝试        136 次
成功打开面板      0 次
靠它识别出精灵    0 只    <- 244 次成功全是 name<-trait 反查
```

每次尝试在战斗里连点 3 下屏幕（落点是**对面 HUD 区域**）、
浪费 3~7 秒。坐标换算本身是对的（`phys_client(2192,95)` -> `2720,149`，
与日志一致），是那个面板在当前渲染下根本点不开。

改成默认关闭，`--foe-scan` 可显式打开。

### 19. 战绩 OCR 胜负串位

```
{"before":143, "after":168, "before_losses":168, "after_losses":14}
```

OCR 会多读出段位/时间里的数字，旧逻辑"靠前关键词配第一个数字"就串了。
改成按关键词就近取数，8 个用例全过（含 3 个真实踩过的噪声场景）。

### 20. 必死换人时替补按满血算

```
06:47:47 v2 lethal switch -> allowed
         (dying this turn (115 hp vs 238 incoming)
          -> switch to 音速犬 which survives)
```

换上的音速犬其实只有 115 血，扛不住 238 —— 白送一只。

根因：`bench_state()` 里所有替补都按 `hp = mx`（满血）上报，
所以 `inc_new < pet["hp"]` 恒成立，等于"随便选一个"。

修法：用 `slot_hp`（在场时记录的真实百分比）折算，
并改成按"扛完还剩多少血"排序，选最健康的那只。

### 21. 误读成 0% 后打印 "recovered (hp 100%)"

整晚 31 次：

```
07:06:16 state battle=True bar=False me=0.0 foe=18.4
07:06:18 FAINT -> recovered (hp 100%) after 0 attempts
```

`me=0.0` 是读不到（血条被遮挡），下一帧读到 100% 就判"恢复"，
把 `faint_at` 清掉，干扰后续真倒下时的判断。

修法：进入 faint 时记 `_faint_hp`，只有当时确实读到低血（`<=5`）
才允许"恢复"，否则静默清掉。

### 22. "技能栏没画"阈值 40s -> 75s

```
07:12:09 T1 SKILL 4
07:12:17 FOE -> 幽冥剑龙 (1.00)      <- 对面换精灵
07:12:13~07:12:43 state battle=False bar=False me=None
07:12:49 match over (no bar 40s)     <- 44s / 1 action
```

对面换精灵后，我方连续 36 秒没轮到。40 秒一到就判结束。

阈值演进：25 秒 -> 40 秒 -> **75 秒**。真结算页/大厅有
「退出」/「开始挑战」按钮这条快路径，不依赖这个兜底。

### 23. 伤害过滤两个方向都错过

```
07:48:50 SKILL 2 damage 220 > foe current hp 111 * 1.5 -> unreadable
07:48:50 SKILL 3 damage 170 > foe current hp 111 * 1.5 -> unreadable
07:48:51 T9 SKILL 1 (skill 1: 121 dmg)     <- 只能选 121
```

1.5 倍太激进，把正常斩杀也挡了。改成 2.5 倍后又漏了 660
（`660 < 380*2.5`）。

正解：用 `foe_now / foe_pct` **反推最大血量**（`foe_max` 在物种
不在库时是 None），然后统一走 1.2 倍判据。

三道闸最终形态：

| 闸 | 判据 | 作用 |
|---|---|---|
| 1 | `v > 900` | 绝对荒谬值 |
| 2 | `v > foe_max * 1.2` | 超过对面总血量（**含反推**） |
| 3 | `v > foe_now * 2.5` | 相对当前血离谱（宽，只挡量级错误） |

### 24. `priority` 列大面积是脏数据

日志里 9/14 的决策带 `priority +5`，包括「火云车」「诋毁」这种普通攻击。
查库：

```
priority 分布: {5: 918, 1: 447, 0: 9, 6: 5, 4: 2, 10: 3, 11: 1, None: 125}
```

**918 个技能是 5**，是默认填充值。真正带先手的只有「先发制人」
（`priority=6`，`desc='造成物理伤害，先手+1'`）。

后果：`acts_first = we_outspeed or priority > 0` 恒为 True ——
机器人以为自己每张卡都先手，高估了所有伤害的收益。

修法：`pri > 1 and ("先手" in desc or "优先" in desc)` 双条件。

### 25. GATE 日志每秒一次，5 分钟刷 54 次

```
energy held: not my turn yet         54 次
press sent, waiting for the turn...  33 次

```

把决策/换人/力竭这些关键信息全淹了。改成同一原因 8 秒一次、
**换原因立刻记**（原因切换本身有信息量）。修后 5 分钟只有 12 条。

## 三、方法论：四次同类错误

这一晚有四次判据错误，结构完全一样 —— **用「某个信号消失」推断状态**，
而那个信号在正常对局里本来就会间歇消失：

| 判据 | 失败方式 |
|---|---|
| `battle=False` 25 秒 -> 结束对局 | 对面上回合被当结束 -> 弃权判负 |
| 我方 HUD 消失 12 秒 -> 结束对局 | 4:3 下血条常读不到 -> 误伤正常对局 |
| `has_exit_button` -> 脱困 | 战斗底部按键也命中 -> 点掉 9 手的对局 |
| **画面静止 8 秒 -> 结束对局** | **对面上回合无动画 -> 28 秒短局** |

四条都已删除或加了硬闸。有效的判据都是「**正面证据**」：

| 正面证据 | 结论 |
|---|---|
| 技能栏画着（4 张规整卡片） | 一定在对局里 |
| 「开始挑战」按钮在 | 一定在大厅 |
| 结算页「退出」按钮 + 不是 VS 页 | 一定在结算 |
| 对面血量上限 / 当前血量 | 卡面伤害的合理性上界 |

以及两个反例教训：

1. **血条位置不能靠运行时搜索**。试过"读不到就按偏移上下搜索"，
   把 `0/417 已倒` 读成 `100%` —— 场景里到处都有满足颜色条件的色块。
   **读不到就报读不到，绝不猜。**
2. **阈值必须用实测分布定**。我方头像阈值 0.72 是"看起来严格"的数字，
   但实测正确族只有 0.57~0.71，等于永远不认。分别统计正确类/错误类
   的分数区间后改成 0.55，识别率 16% -> 75%。

### 阈值/超时的取舍原则

凡是"多久没看到 X 就认为状态变了"的判据，都问一句：
**X 在正常状态下会不会自然消失？**

| 判据 | 正常状态下会消失吗 | 处置 |
|---|---|---|
| 技能栏 | 会（对面上回合） | 超时放宽到 75 秒 |
| 我方血条 | 会（4:3 读不到） | 只当 90 秒长兜底 |
| 画面变化 | 会（对面无动画） | **删除** |
| 底部白胶囊 | 会（战斗按键区） | 加技能栏硬闸 |

## 三、新增能力

### PvP 大数据（`src/pvp_meta.py`）

从 169 套真实天梯阵容 + 1228 只种族值，给出**概率分布**而不是单点：

```
寂灭骨龙  样本 35
  性格  固执 49% / 平和 31% / 慎重 6% ...
  HP    425 (65.7%) / 490 (34.3%)
  物防  191 (5.7%) / 207 (88.6%) / 238 (5.7%)
  携带  隼鳞 91% / 偷袭 60% / 吓退 54% / 电弧 51% / 先发制人 43%
  伤害 213 -> p10=43.5% 中位=50.1%，>=50% 概率 65.7%
```

详见 `docs/PVP_META.md`。

### 对手行为模型接入决策

`opponent_log` 采集 -> `opponent_model` 三层池化 -> `anticipate` 预判
-> `policy_v2` 用进决策。日志里能看到：

```
T1 SKILL 2 (... [v2 0.2004] [对手 攻28% 换51% 增21% global n=230])
```

详见 `docs/OPPONENT_MODEL.md`。

### 先发制人

`skills` 表本来就有 `priority` 列，整条链路从来没读过。现在：

- 这回合会死 + 先发技能能反杀 -> 用先发技能（不换人）；
- 先发技能在速度之前结算（`acts_first = we_outspeed or priority > 0`）；
- 不会因为 priority 高就压过明显更高的伤害。

### 借用技能识别

借用/取念用出去后卡面会变成复制来的技能、**会画伤害数字**。
