# 计划：技能卡伤害读数的多帧稳定化

## 问题（2026-11-21 实盘，已确认）

同一只精灵（音速犬）、同一个对手（饮雪狂兽）、血量全程 100% 不变，
但卡面伤害读数整组乱跳：

| 回合 | slot1 | slot2 | slot3 | slot4 |
|---|---|---|---|---|
| T4 | 120 | **350** | **60** | – |
| T5 | – | **350** | **60** | – |
| T6 | 240 | **350** | **60** | – |
| T7 | 150 | **350** | **60** | – |
| T8 | `15?` | 196 | **420** | 335 |
| T9 | 153 | 120 | 50 | 55 |

T4–T7 连续 4 次 s2=350 / s3=60，是真值。
T8 三个槽位**同时**变成 196/420/335 —— 不是单个数字识别错，是**整组错位**。

### 机制

`perceive._slots` 对缺失槽位的数字位置是**推断**的：

```python
xs_known = sorted(int(s["box"][0]) for s in slots if s)
col = xs_known[len(xs_known) // 2]     # 已有槽位的列中位数
bx0 = max(0, col - 70)
bx1 = min(w, col + 120)
```

一旦某个槽位没检出（pills 漏检、动画遮挡、卡面高亮），
推断出的列偏移就会把**相邻卡片的数字**框进来，整组读数一起错。

### 后果

T8 读到 slot3=420 → 判定 `kill`（420 ≥ 对手 78% 血）→ 打出去实际只有 60 伤害。
这类错误决策直接浪费回合，而"能杀就杀"是最关键的判据。

## 修复方案

### 新增 `src/skill_reader.py`：多帧投票

不改 `perceive` 的识别逻辑（它已经足够复杂，动它有回归风险），
而是在**识别之后、决策之前**加一层稳定化：

```python
class SkillStabilizer:
    def update(self, skills) -> list:
        """喂入一帧读数，返回稳定后的读数。"""
```

规则：

1. **按精灵身份分桶**：换精灵后历史必须清空（不同精灵的卡不同）。
2. **每槽位保留最近 N 帧**（N=5），取**众数**；平票取最新。
3. **置信度**：某值出现 ≥2 次才采用；只有 1 帧时**原样返回**（不阻塞首回合决策）。
4. **整组错位检测**：如果本帧 ≥3 个槽位同时与历史众数不同，
   判定为"整组错位"，**丢弃本帧**（保留历史）。这是针对 T8 那种情况的直接对策。
5. **过期清理**：连续 M 帧（M=3）没出现的旧值降权，避免卡面真的变了
   （升级、buff 加成）之后一直用旧值。

### 接入点

`robot._battle_tick` 里 `st = self.perc.observe()` 之后：

```python
st["skills"] = self._stabilizer.update(st["skills"], st.get("my_pet"))
```

稳定化只影响**决策输入**，不影响 `turns.jsonl` 的原始记录
（原始数据保留，方便复盘时对比）。

### 权重

不改 `policy_weights.json`。这是识别层修复，不是策略调参。

## 验收标准

1. `src/test_skill_reader.py` 单测通过：
   - 连续 4 帧 350/60 -> 输出稳定 350/60
   - 第 5 帧整组错位 -> 丢弃，仍输出 350/60
   - 换精灵 -> 历史清空，不串
   - 只有 1 帧 -> 原样返回
2. 实盘日志里不再出现"同一只精灵相邻回合伤害翻倍/腰斩"。
3. `turns.jsonl` 原始记录不受影响（仍是单帧值，便于对比）。

## 不做的事

- 不改 `perceive._slots` 的列推断逻辑（风险高，且多帧投票能覆盖）
- 不引入新的 OCR 模型
- 不动 `digitread` 的模板
