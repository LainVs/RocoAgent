# 计划：对面身份定标（HUD vs 立绘，到底该信哪个）

> 2026-11-21 · 代码：`src/portrait_calib.py`、`src/test_portrait_fusion.py`
> 改动：`src/portrait_onnx.py`（融合策略）、`src/imgio.py`（中文路径）

---

## 0. 先说一个命名误解

日志里 770 次 `FOE -> id conflict hud=X portrait=Y -> use hud`，
注释写的是 **"HUD 说…（游戏界面显示的，绝对正确）"**。

**这句话是错的。** `hud_result` 不是读游戏界面上的名字，而是
`portraits.identify()` 对着 `assets/portraits_foe/` 这个**自己收集的头像库**
做模板匹配的结果。日志里叫 "hud" 是历史遗留。

所以"绝对正确"这个前提不成立 —— 下面是量出来的数字。

---

## 1. 定标方法

`src/portrait_calib.py` 用 145 张**人工标注过的**敌方头像（`assets/portraits_foe/`，
跳过 1 张标注为 `None.png` 的坏数据）同时评估两条通道：

| 通道 | 是什么 | 怎么测 |
|---|---|---|
| 立绘 ONNX | roco-cal 620 类分类器 | 直接跑 `predict()` |
| 模板匹配（"hud"） | 对着自己的头像库做 `matchTemplate` | **留一验证** |

留一是必须的：样本本身就是库里的文件，不排除自己会以 score=1.0 匹配到
自己，准确率虚高到 100%。

### 1.1 一个必须先修的问题：变体后缀

模型类别名带变体后缀，我们的标注是基础名：

```
标注 加油蟹   -> 预测 加油蟹（单只海葵的样子） 0.89   ← 其实猜对了
标注 化蝶     -> 预测 化蝶（平常的样子）       0.67   ← 猜对了
标注 卡瓦重   -> 预测 卡瓦重（草地附近的样子） 0.66   ← 猜对了
```

直接比对会把"猜对变体"算成错，把准确率从 ~95% 压到 **74.7%**。
归一化（去掉 `（...）`）之后才是真数字。

## 2. 结果

```
立绘 ONNX  Top-1 82.8%   Top-3 87.6%
  置信度 >=0.90   118 张   93.2%   ← 覆盖 81% 样本
  置信度 0.70~0.90  8 张   50.0%   ← 等于抛硬币
  置信度 0.50~0.70  6 张   50.0%
  置信度 <0.50    13 张   23.1%   ← 比瞎猜还差

模板匹配（留一） Top-1 42.1%
  score >=0.85     37 张   94.6%   ← 准确，但只覆盖 26%
```

**两个通道的形态完全相反**：

- 立绘：整体准（82.8%），高置信区间覆盖广（81%）
- 模板：整体差（42.1%），只有高分段准，且覆盖面窄（26%）

而旧策略是"模板有结果就用模板" —— 等于**优先用了差的那个**。

### 2.1 为什么模板通道在生产里看起来"很准"

生产里模板库包含**同一场战斗**里刚存的帧，所以经常以 0.98~1.00 匹配到
几乎相同的那一张。留一验证量的是"没见过的对手"，那才是 42.1%。

换句话说：模板通道擅长**记住见过的**，不擅长**认出没见过的**。

## 3. 改了什么

### 3.1 融合策略（`portrait_onnx.identify_fused`）

旧顺序：模板优先 → 模板没有才用立绘。

新顺序：

```
1. 立绘 conf >= 0.92 且连续 2 帧  -> 用立绘   （定标 93.2%）
2. 否则 模板 conf >= 0.60          -> 用模板
3. 否则 立绘 conf >= 0.85 且连续 2 帧 -> 用立绘
4. 都不满足                        -> 保持 prev（绝不抖）
```

- 0.92 而不是 0.90：比定标置信区间再保守一点，也和原来"已有认定时
  改用新答案"的门槛保持一致
- 仍然要求**连续 2 帧**：立绘框里会混入背景和 NPC，单帧答案会跳
  （实测 01:12 连续给出 绿草精灵/白瑟/燃薪虫）
- 阈值可用 `onnx_override=` 覆盖，便于快速回滚

### 3.2 顺带修掉：中文路径读图

定标时发现 `cv2.imread("水灵.png")` 在 Windows 上返回 `None` ——
OpenCV 走 ANSI 代码页，读不了中文文件名。而**头像文件名就是精灵名**。

这类失败**不报错**，上游通常当成"这张是空的"跳过，属于沉默失效。

新增 `src/imgio.py`（`read` / `write`，走 `np.fromfile` + `imdecode`），
替换了 4 处裸 `cv2.imread`：`ui_server`（2 处）、`ocr_batch`、`skill_names`。

`portraits.py` 早就有自己的 `_imread/_imwrite`，没动它。

## 5. 真实效果的边界（必须说清楚）

这次定标用的是**已保存的头像裁剪图**，比生产里的实时 ROI 更干净
（实时 ROI 会包含背景和 NPC）。所以：

- **93.2% 是上限估计**，实盘会更低
- 生产里已有"连续 2 帧"的门槛来压抖动，这次没动它
- 如果要真实数字，得在实盘里记录 `foe_name` + 最终胜负，再用
  `matches.py`（场次 id）回溯 —— 这一步依赖实盘数据，暂时做不了

**回滚方式**：`identify_fused(..., onnx_override=1.01)` 即可完全退回旧行为
（1.01 意味着立绘永远不满足条件）。
