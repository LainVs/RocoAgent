## 这些 bug 为什么长期没被发现

1. **测试把错误抄进去了**：`test_session_moves` 的 "live frame ROI" 用例
   复制粘贴了一份 ROI 计算（`ya+5:yb+95`），等于用错误实现验证错误实现，
   `read_band` 怎么改都 PASS。
2. **静默 return**：卡面没画全时直接返回，不写日志，于是"功能不生效"
   和"代码没执行"看起来一模一样。
3. **没有 raw 回传**：`conf 0.79` 只说明"匹配得不够好"，看不出 OCR
   到底读成了什么。加上 `raw=` 后一眼就看出是 `251 跌落` 这种数字污染。

对应补的测试：

- `test_skill_pill_boxes`：断言传给 Screen 的矩形是 `(x0,y0,w,h)`；
  部分卡面时必须返回长度 4 且缺槽为 None
- `test_pet_at`：AST 静态锁住"`pet_at = now` 必须在身份变化分支内"
- `test_session_moves`：死锁回归（2s 超时守护）；ROI 用例改为直接调
  `read_band` 并用真帧断言能读出 `力量增效` / `跌落`

## 遗留问题（下一步）

**槽位与卡面错位**。失败样本有清晰规律：

```
raw='扬沙'     —— 属主 迪莫/蒲公英娃娃，不属于 冰钻布鲁斯/卡瓦重
raw='岩脉崩毁' —— 属主 地鼠/遁鼠/遁地鼠，不属于 音速犬
```

字读得**很干净**（1.00），但被正确拒绝 —— 因为读到的是**邻卡的名字**。
`_slots` 的 lattice 在第一/最后一张卡缺失时会整体平移一档，
于是 slot N 的 box 指向了 slot N±1 的名字带。

好的一面：本宠技能池这个约束**拦住了所有跨精灵误配**，所以错位只会
导致"读不到"，不会导致"读错"。这是安全的失败模式。

修法方向：用**技能池反查**做槽位对齐 —— 4 张卡的名字带一次性全读，
再在池内做最优分配（匈牙利/贪心），而不是逐槽位读。这样天然免疫平移。
