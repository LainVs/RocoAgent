# 计划：两级词表改为"配置 ∪ 可学池"，而非"配置优先独占"

## 问题（本轮实机发现）

```
09:28:16 BAND -> 音速犬 槽1 未识别 (conf 0.00 < 0.80) raw='香噬' vocab=4(config)
09:28:38 BAND -> 音速犬 槽1 未识别 (conf 0.00 < 0.80) raw='香噬' vocab=4(config)
09:28:54 BAND -> 音速犬 槽1 未识别 (conf 0.00 < 0.80) raw='香噬' vocab=4(config)
```

实测三份词表对 `香噬` 的表现：

| 词表 | 大小 | Ocr.match | _unique_near |
|---|---|---|---|
| config（音速犬配置） | 4 | None 0.00 | **None**（拒） |
| species（可学池） | 44 | 吞噬 0.50 | **吞噬**（唯一，可采纳） |
| all（全库） | 1045 | 吞噬 0.50 | 吞噬 |

「吞噬」在音速犬的可学池里 = **True**，在配置里 = **False**。

**配置过期时，「配置优先独占」会挡住合法的可学技能。** 用户实机换了
技能（槽1 从「借用」改成别的），配置没跟上，那 4 个词就不完整了 ——
此时仍只拿这 4 个词当**唯一**词表，等于把用户的可选范围砍掉。

## 为什么当初这样设计

上一轮修「扬沙」时，问题是 `species_skills` **漏了**扬沙，
所以需要 `my_team` 配置来补。当时写成"配置优先独占"（if own: use own）。

这个写法对「补漏」有效，但对「配置过期」有害 —— 两种场景的需求相反：

- 「扬沙」：`species_skills` 缺 → 需要配置补
- 「香噬」：配置缺（过期）→ 需要可学池补

**两者都需要，所以应该取并集，不是二选一。**

## 修法：并集，但保留层级信息用于诊断

```python
own = _owned_vocab(db, pet)          # 4 词
learn = _learnable_vocab(db, pet)    # 40~60 词
if own or learn:
    vocab = 去重(own + learn)         # 并集
    tier = "config+species" / "config" / "species"
else:
    vocab = _all_vocab(db)            # 1045
    tier = "all"
```

### 安全性影响评估

并集会不会引入误配？必须实测：

1. **唯一性兜底**：词表从 4 变到 ~48，唯一候选更难成立 —— 
   **这对安全是有利的**（更多候选 = 更容易多候选 = 更倾向拒绝）。
   实测 `香噬` 在 44 词池下仍唯一指向「吞噬」，可采纳。
   但 `扬沙` 在 44+4 词下会不会多候选？需要验证。

2. **Ocr.match 标准匹配**：分母变大，同一错读的分数会降。
   `扬沙` 在配置 4 词时 1.00，并入可学池后可能降 ——
   **但扬沙本来就不在可学池**（这是数据不全的事实），
   所以并集后它仍在，分数只取决于「配置里这一条」。

   等等，这里有个关键点：`ocr_cn.Ocr.match` 的分数怎么算的？
   如果它是"与最相似候选的相似度"，分母不影响；如果是"与词表
   整体的归一化"，分母就会影响。**必须实测。**

3. **门槛**：现在 `thr = 0.80 if len(vocab) < 60 else 0.90`。
   并集后 vocab 可能 48~64，**跨过 60 门槛会突然跳到 0.90**，
   导致原本 0.85 的匹配突然被拒。这是个隐蔽的边界 bug。

## 必须先查清的 3 件事

1. `ocr_cn.Ocr.match` 的分数是否受词表规模影响（读源码）
2. 并集后「扬沙」分数是否仍 >= 门槛
3. 并集后「香噬」是否仍唯一指向「吞噬」

## 验收

- `扬沙`（配置有、可学池无）仍能采纳
- `香噬`（配置无、可学池有）能采纳为「吞噬」
- 配置外且可学池外的词仍被拒
- 门槛边界：词表跨 60 时不出现"分数没变但门槛跳变"的回归

## 若门槛边界有风险

把门槛改成基于**匹配来源**而不是词表规模：
- 标准匹配：0.80（统一）
- 唯一性兜底：不受门槛约束（它自带唯一性保证）
这样就没有"词表跨 60 跳门槛"的陷阱。
