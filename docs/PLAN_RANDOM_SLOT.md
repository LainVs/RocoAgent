# 计划修正：BAND 必须识别「随机技能位」—— 之前整轮诊断方向错了

## 用户提示救了我

用户让我"查一下借用的技能效果"。查完发现：

```
【借用】effect_id 21320010
  buff name: "随机"
  buff desc: "随机到了【@ACS】技能"
  power=0, cost=0, priority=5
```

**「借用」的效果是"随机获得一个技能"，卡面显示的是被随机到的技能名。**

同类技能还有两个（同 effect 家族）：

| 技能 | effect_id | 效果 |
|---|---|---|
| 借用 | 21320010 | 随机到了 {技能} |
| 取念 | 21320020 | 随机到了 {技能} |
| 复写 | 21320030 | 随机到了 {技能} |

## 这解释了全部"异常"现象

音速犬 `my_team` 槽1 配置 = **「借用」**。它的卡面名字在每次上场时**随机**：

```
07:07 火焰切割
08:11 崩拳
08:34 反击拳
08:54 影袭
09:46 叠浪
09:58 主轴
10:08 岩脉崩毁
10:18 漫反射
```

而槽2/槽3/槽4 在同一时段内始终稳定（诉毁→诋毁、闪光冲出→闪光冲击）。

**每次上场内名字稳定、跨上场变化** —— 完全符合"借用随机一次后固定"的机制。

我之前把这些当成了三个 bug：

| 我当时的判断 | 实际 |
|---|---|
| "槽位错位，读到邻卡" | ❌ 就是本槽位的随机技能 |
| "身份抖动，my_name 卡在旧值" | ❌ my_name 一直是对的 |
| "OCR 不稳，同一槽位读三个名字" | ❌ 游戏机制使然 |

## 我可能已经引入了错误改动

### 危险改动 1：`_ident_confirmed` 门禁（`ed58d07`）

我为"换人后身份未确认"加的门禁，理由是 09:46 那次读到「叠浪」。
但「叠浪」就是借用随机到的技能 —— **身份从来没错**。

这条门禁会在换人后 1~3 秒跳过 BAND。虽然代价不大，但它是基于错误
诊断加的，且它假设"读到的技能必须属于当前精灵的可学池"——而这个
假设对随机技能位**根本不成立**。

### 危险改动 2：「配置 ∪ 可学池」并集（`c8b2b6f`）

并集本身是对的（解决「扬沙」缺失），但**它仍然假设"读到的名字必须在
词表里"**。对随机技能位，随机到的可能是全库 1045 个技能里的任何一个
（含音速犬完全学不了的「叠浪」，水系）。

所以 BAND 对随机技能位会**永远失败**，无论词表多大。

## 正确的修法

### 核心认知：随机技能位不能用"技能池"校验

对「借用/取念/复写」所在的槽位：
- 卡面名字**不受该精灵技能池约束**（可以是全库任意技能）
- 名字**每次上场可能变化**（不能当作稳定事实缓存）
- 但**必须仍然读出来**（策略需要知道当前随机到了什么技能）

### 实现要点

1. **识别随机技能位**
   `_band_vocab` 已有 `own = _owned_vocab(...)`，若某槽位的配置技能
   ∈ {借用, 取念, 复写}，则该槽位标记为随机位。

2. **随机位的词表 = 全库**（1045 个）
   而不是该精灵的可学池。门槛用 0.90（全库匹配，必须更严）。

3. **随机位不写入 `session_moves`**
   或者写入但标记 `source="band-random"`，并且**每次上场作废**。
   因为名字会变，永久缓存是错的。

4. **随机位不参与"配置过期"判定**
   它和配置不同是**正常的**，不该触发 `stale`。

5. **撤销/放宽 `_ident_confirmed` 门禁**
   它基于错误诊断。保留它也无害（换人后 1~3 秒），但不再需要。
   更重要的是：它无法解决随机位问题，别指望它。

## 需要验证的事

1. 随机位的名字在**同一上场内**确实稳定？（时序数据支持，但要确认）
2. 随机到的技能是否总是全库技能，还是有范围限制（如只随机同属性）？
3. 是否只有「借用/取念/复写」这三个，还有别的改卡面名机制吗？

## 立即行动

1. 先撤销对「借用」位的错误处理思路，加随机位识别
2. `session_moves` 对随机位单独标记，不污染配置校验
3. 把这三轮文档里"错位/抖动/OCR 不稳"的结论更正为"随机技能位"

## 教训

我连续三轮把**游戏机制**当成**代码 bug** 在修，还为此加了门禁、
改了词表、写了三份"结果"文档。根因是我一直在看"日志里名字不一致"，
却没有去查**这个技能本身是什么效果**。

数据和机制类问题，第一步应该是查数据，不是看日志猜。
