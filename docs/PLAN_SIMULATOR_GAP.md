# 模拟器对比：洛克PVP助手 vs RocoAgent（结论：它没有模拟器）

> 结论先行：**它没有实现对战模拟器**。教程里的「模拟空间」是数据导入入口，
> 不是模拟引擎。但我们双方手里各有一半拼图，拼起来能做出 1:1 真实模拟器。

---

## 一、它有什么 / 没有什么

### 有（资产级）
1. **官方伤害内核 k0-damage.js** —— 从游戏客户端 runtime.js 逆向的公式，
   含 float32 逐位舍入、多段伤害、能量修正。我们已验证与我们的
   `statmodel.damage` 逐位一致。
2. **官方数据包**（PAK 解包）：
   - `authority/skill.json` 2032 条（比我们导的 1655 多，含 GM/测试技能）
   - `roco_buff_calc_map.json` —— **buff 数值计算映射**：
     「物攻等级提升」→ `phyAtkPercent: 10`，「最好的伙伴」→ 双攻双防速 +20%
     —— **buff 等级 → 精确百分比**，这是模拟器最缺的一块
   - `authority/buff.json` 1.7MB 完整 buff 效果
3. **官方 800 只 PVP 使用率**（`pokedex_800_pvp_usage_v340.json`）：
   - 性格分布（音速犬：开朗 37.87% / 固执 18.65%）
   - 技能携带率（银月狼王：撞鬼 90.04% / 月蚀 75.05%）
   - **个体投资分布**（物攻 82.84% / 速度 81.71%）
   - 血脉分布（首领 65.71%）
   - 数据源：`wegame.shallow.ink/api/v1/games/rocom/ingame/pet/stat`（官方接口）
4. **模拟空间 pet 覆盖表**（simulation-space-covered-pets.json 283KB）

### 没有
1. **对战模拟引擎** —— `K2 穷举内核` 是空壳（`IMPLEMENTED=false`，
   调用直接抛 `ExhaustiveNotAvailableError`）；B1/B2 只算**单次伤害区间**，
   不推演多回合
2. 主 bundle（3.7MB dat）里搜不到 模拟/推演/预测 等关键词
3. 教程原文：「模拟空间，模拟器会自动对局进行推演战况，需要数据通过模拟空间进行分发，持久和精密集，不太经常使用」
   —— 这是**把别人的对战记录导进它的数据库**的功能，不是自研模拟

---

## 二、我们有什么 / 缺什么

### 有（`src/simulator.py` 19KB，可运行）
- `Dex`：精灵/技能数据访问（roco-cal 数据）
- `Pet`：场上精灵（血量/能量/buff 槽）
- `calc_damage`：走 `damage_v2`（=官方公式）+ type_effect + stab + buff
- `run_match`：完整跑一局（换人/聚能/必死/换人冷却）
- 三种策略：Greedy / Smart / Buff（BuffPolicy 用 roco-cal 真实 buff 中位值）
- `selfplay --selfplay 8` 可跑：8 局贪心自对弈，平均 16 回合

### 缺（对照官方公式逐一核实）
1. **buff 精确数值** —— 现在用 `ATK_BUFF_MEDIAN=0.70`（中位近似），
   官方有 `roco_buff_calc_map` 的**逐条精确值**（物攻+10%/+20%...）
2. **个体/性格分布** —— 自对弈双方都是"标准面板"；官方 800 只使用率
   能生成**真实分布的对手**
3. **效果链**（控场/吸血/连击/反伤）—— 只实现攻击+buff 一类
   （代码注释自述"敌方技能暂不模拟"）
4. **energy 规则**（击杀回能、惊吓盒子扣能）—— 官方效果链有数据

## 三、1:1 真实模拟器路线（借用它的数据，用我们的引擎）

| 步骤 | 做什么 | 用它的什么 | 预计工作量 |
|---|---|---|---|
| S1 | buff 精确值：`ATK_BUFF_MEDIAN` → 按 buff 名查官方 map | `roco_buff_calc_map.json` | 小（1 个映射表） |
| S2 | 对手生成器：按官方使用率抽样性格/个体/技能携带 | `pokedex_800_pvp_usage` | 中（分布抽样） |
| S3 | 自对弈校准：模拟器胜率 vs 实盘胜率（29%）对齐 | — | 中（是模拟器可信度的唯一检验） |
| S4 | 效果链：吸血/连击/反伤（official_kind 已分类的 control 族） | `authority/buff.json` | 大（按需逐个实现） |

**S1+S2 完成后**：模拟器能回答「我方这套阵容，对上官方天梯最常见的
配法，胜率多少」—— 这正是配队和策略调参需要的。

**验收标准（不做完不算数）**：
- S1：模拟器里「物攻等级提升」的增伤与官方百分比一致
- S2：抽样的对手面板分布与官方使用率 KS 检验不拒绝
- S3：模拟器预测的最优技能选择与实盘日志的重合率 ≥ 80%

## 四、为什么它的"模拟空间"不是模拟器

教程原文：「模拟空间，模拟器会自动对局进行推演战况，需要数据通过
模拟空间进行分发」——结合 `simulation-space-covered-pets.json`
（只是一张覆盖清单），它做的是**导入他人对战记录做回放**，
不是从零推演。真正的推演内核 K2 它标记为 `IMPLEMENTED=false`。
