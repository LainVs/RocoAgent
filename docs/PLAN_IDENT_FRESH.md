# 计划：身份不可信时，禁止用旧 my_name 的技能池做 BAND 校验

## 问题（本轮实机证据，09:4x）

```
09:46:14 PET -> 音速犬 (ONNX 1.00)     <- 最后一次成功识别
09:46:39 BAND -> 音速犬 槽1 raw='叠浪'  vocab=44(config+species)
09:46:55 BAND -> 音速犬 槽1 raw='叠浪'
09:46:58 BAND -> 音速犬 槽1 raw='叠浪'
09:48:58 FORCED SWITCH -> panel is up  <- 场上换过精灵
09:49:05 PET -> 恶魔狼 (ONNX 1.00)     <- 换人成功
```

关键事实：

- 「叠浪」属主仅 9 只，**全是水系精灵**（水滴兽/水蛇兽/深渊兽…），
  音速犬（火系）学不了它
- dump 图 `band_音速犬_1_1795398392_ctx.png` 里卡面清楚是「叠浪」，
  且美术是**蓝色水系**，与之前「反击拳」的橙红拳套完全不同
- 同窗口 `unknown bust` 出现 **9 次**，ONNX 持续失败
- 槽2/槽4 读到的「诋毁」「闪光冲击」确实属于音速犬

**结论：场上精灵换过，但身份识别在这段时间全部失败，`my_name`
卡在旧值"音速犬"。BAND 于是用音速犬的词表去校验真实卡面，必然失败。**

## 为什么槽2/槽4 能对上

这两张卡读到的「诋毁」「闪光冲击」恰好也属于音速犬 —— 但更大的可能是：
换人后新精灵的技能**恰好**与音速犬有重叠（「诋毁」有 111 个属主，
「闪光冲击」33 个）。也就是说槽2/槽4 的"成功"可能也是巧合。

这比"读不出来"更危险：它会让错配的技能名被写入 `session_moves`，
进而污染策略。

## 修法：身份新鲜度门禁

在 `_maybe_band_scan` 里加一条前置条件：**只有身份在近期被成功确认时
才做 BAND**。

判据：距最后一次**成功**身份识别（ONNX/avatar 采纳）
不超过 `IDENT_FRESH_S`。建议 20 秒 —— 一次换人动画 + 两三个回合，
足够覆盖正常节奏；超过就说明识别已经不行了。

配套改动：
1. `_check_active_pet` 在**成功采纳**时记 `self._ident_at = now`
2. `_maybe_band_scan` 加 `if now - _ident_at > 20: return`（打限流日志）
3. 换精灵重置 `_ident_at = 0`（强制要求重新确认）

## 为什么不用"投票/多数"来兜底

`unknown bust` 时分数是 0.04~0.12，属于**识别器完全失效**，
不是"低分但接近"。这种情况下任何投票都是在噪声上做决策。

## 与既有修法的关系

- 前面修的 `pet_at` 解决"1.2s 稳定窗口永远不成立"
- 这条解决"身份过期但窗口仍然打开"
两者互补：`pet_at` 管**刚换精灵**，`_ident_at` 管**长时间认不出**。

## 验收

1. 正常情况下 BAND 仍工作（音速犬 4/4、银月狼王 3/3 等已验证）
2. 身份失效 20s 后，BAND 停止写数据，日志给出明确原因
3. 不再出现"用甲的技能池校验乙的卡面"这种必然失败的组合

## 风险

如果 ONNX 在某些场景（如暗色背景、特效遮挡）长期认不出，会连带
停掉 BAND。但这是**正确取舍**：用错的词表读出来的东西不可信，
写入 `session_moves` 后危害更大（会污染策略）。

日志里会明确写 `BAND skip: identity stale (Ns)`，能一眼看出是哪种情况。
