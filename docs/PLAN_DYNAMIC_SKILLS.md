# 卡面下方其实印着技能名 —— 动态解析我方技能的突破点（2026-11-22 深夜）

## 一、关键发现

在真实抓帧（`logs/f0.png / f1.png / k1.png`，同一布局三帧）上验证：

**每个伤害胶囊的正下方（pill 下缘 +0~40px、左右各扩 70px）印着技能名。**

| 帧 | pill1（dash）下方 | pill3 下方 | pill5 下方 |
|---|---|---|---|
| f0 / f1 / k1 | `矿物置换` | `碎银` | `突袭` |

三帧完全一致，封闭词表匹配得分 **1.00**，且都是真实技能：

```
碎银      id=8000078  power=None cost=10  魔法
矿物置换  id=8000077  power=None cost=1   状态
突袭      id=7020450  power=70   cost=2   普通
```

这意味着：**我方技能不需要 my_team 表、不需要耗能指纹推断，
卡面自己就写着名字**。`my_team` 从"依赖"降级为"加速缓存"。

顺带的修正：之前 `badge_tight`/`cost_digit` 探针找不到"耗能数字"是
对的 —— **卡面上根本没有独立的耗能徽章**。那个黄色圆盘里的暗色笔画
是装饰纹路（阈值 110 下是细斜线，不是数字）。耗能只能靠
1) 播报出招前后的能量差，或 2) 查库（拿到技能名后）。

## 二、成本实测

| 途径 | 耗时 | 结论 |
|---|---|---|
| RapidOCR 读下方名字带（2.5x 放大） | **1.5 s/卡** | 不能每帧跑 |
| 封闭词表匹配（1510 技能） | 7.4 ms | 便宜 |
| digitread 主胶囊（伤害数字） | ~0（已在跑） | — |

1.5s × 4 卡 = 6s，**只在换精灵后做一次**，之后按 (pet, slot) 缓存。
这和现有 `foe_ident` 的节流思路一致，不会挤占决策窗口
（换人后的 1~2 秒本来就在等 UI）。

## 三、修正后的三层降级链

```
第一层  会话缓存    (pet, slot) -> 技能名，跨局复用，落盘 data/session_moves.json
第二层  卡面直读    换精灵后一次性 OCR 名字带 -> 封闭词表 1.00 才采纳
第三层  my_team 表  命中且与观测不矛盾才用（表过期会被观测纠正）
```

其中第二层是新增能力，也是新主路径。名字带还有两个用途：

1. **校验器**：无论技能名来自哪一层，都可以用
   `卡面伤害 ≈ outgoing(my, foe, skill_name)`（含本系/克制的自算，
   昨天已修好）做交叉验证；矛盾 2 次 → 撤销确认。
2. **my_team 过期检测**：直读名字 ≠ 表配置名字时，日志报
   `TEAM STALE: slot N 表=X 实读=Y`，提示用户跑 `team_audit`。

## 四、已知边界

- 名字带只在卡**画出来**时可见（我方回合）；换精灵后第一帧就抓，
  一次 OCR 6 秒内完成，期间不阻塞决策（缓存 miss 的槽位按 unknown 处理）。
- `矿物置换`/`碎银` 是 power=None 的状态技，卡面主胶囊画 `--`，
  但下方名字照样印 —— 恰好覆盖了 `_fix_status_kinds` 最难的那类。
- OCR 对 2~3 字名可能错 1 个字；封闭词表 + 编辑距离 1 的匹配规则
  （`ui_server._edit1` 已有）可以兜住，分数 <0.90 不采纳。
- 4 张卡的 ROI 几何还没标定成常量（当前探针用 pill box 相对偏移，
  已在三帧上稳定）。

## 附：替补的技能解析边界（2026-11-22 深夜确认）

session_moves 的三层链只覆盖**当前在场**的精灵——替补在 HUD 上没有
卡面、没有播报，技能无法在线学习。影响面：

- 换人评分（policy_v2 的 switch 分支）用 `best_damage_from`（可学池
  取 max）评估替补输出——已有 switch_ko_discount 打六折兜底，不会
  触发 KO 幻想
- 替补的承伤评估（`_incoming`）同样走池级最坏+加权，与在场精灵一致
- **替补一旦上场**，名字带扫描 + 播报确认立即接管，2 回合内补全

结论：替补技能不可知是 HUD 的物理边界，不是解析缺口。换人评分的
保守方向正确（低估替补输出好过高估），无需改动。
