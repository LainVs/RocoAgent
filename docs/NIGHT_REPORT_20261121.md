## 三、最重要的三个发现

### 1. buff 策略胜率 +14%（模拟器验证）

同队自对弈（排除队伍差异），各 150-200 局：

```
greedy vs greedy   52.0% / 48.0%   基准
buff   vs greedy   66.5% / 33.5%   +14.5%
smart  vs greedy   37.5% / 62.5%   换人不如纯输出
```

**参数搜索找到明确拐点**：
```
buff_bonus 0.06 -> 50.3%（当前值，从不叠）
buff_bonus 0.10 -> 64.3%（拐点）
buff_bonus 0.26 -> 64.3%（再高无收益，说明叠一次就够）
```

### 2. 特性不是"身份键"，是"伤害乘区"

roco-cal 的 262 个特性定义里：
- **104 个影响战斗**（stat_buff 54 / power_multiplier 26 / …）
- **158 个不影响**（`共鸣` 只加虫鸣威力 +20，跟属性无关）

这解释了为什么 27 只属性各异的精灵共享「共鸣」——
它本来就跟属性无关，我们之前用它反查属性是错的方向。

### 3. 识别必须用"角色立绘"，不是 HUD 头像

```
喂 HUD 头像 84x76     -> "000无" 1.00（框里没内容）
喂角色立绘 21%x30%    -> "燃薪虫" 0.94~1.00
```

标定结果（330 张真实战斗帧网格搜索）：
```
敌方 x=0.645 y=0.355 w=0.075 h=0.195  置信 0.759  非空率 95%
我方 x=0.225 y=0.55  w=0.09  h=0.15   置信 0.770  非空率 100%
```

## 五、对手行为模型（骨架就位）

按你的需求建了完整链路：

```
opponent_log.py    每回合记录对面行为（attack/switch/buff）
     ↓
opponent_model.py  按 (我方,对面) 聚合概率 + 换人前三
     ↓
anticipate.py      预判建议（对面偏防御->叠buff；偏换人->针对换上那只）
```

**当前数据量**：2238 条去重回合 / 93 组对位 / **仅 1 组样本充足**。

样本不足时 `advice()` 返回 `None`，不影响现有决策——
这是刻意的设计：**宁可不用，也不能用噪声决策**。

## 九、第二轮修复（04:00 - 05:00）

第一轮之后机器人稳定了，但复盘日志又发现 5 个问题，全部修掉。

### 1. 战绩读取从没成功过（`4e494b5`）

```
results.jsonl 从 2026-11-19 09:29 起就没再写入，整整两天
record ocr[1]/[2]/[3] 三次全空
```

根因：「历史战绩」按钮**只在大厅有**，而代码在 `match_ended_at`
后 8 秒内就读 —— 那时还在结算页，点击落在空白处。

修：加 `_in_lobby` 判据（用 `has_start_button` 确认在大厅），
窗口从 8 秒放宽到 180 秒（结算→升段→大厅需要时间），
`_rec_done_for` 只在真读到才标记。

### 2. 换人评分 "dmg 0 taken 0"（`39c944e`）

```
FAINT -> switch slot 5 (银月狼王 dmg 0 taken 0, attempt 6)
```

根因：`pvp_engine.pet()` 只查 roco-claude 的 json（499 只），
银月狼王/冥古龙/形态变体都查不到。

修：pet() 改为 DB 优先（1228 只），加形态变体回退
（"黑化加尔（黑化的样子）" → "黑化加尔"），
worst_incoming 改用 statmodel 直算。

```
银月狼王 vs 帅帅魔偶   打 0 → 505   挨 None → 239
冥古龙   vs 黑化加尔   打 0 → 242   挨 None → 261
```

### 3. 替补名字从没被识别（`f5abd22`）

```
PANEL MAP: no model data (slot2:no-name,slot3:no-name), bench={1:'音速犬'}
```

根因：`bench_names` 只在 `_check_active_pet` 里填过**当前上场那只**，
替补从来没被识别过。

修：用 team_db 的队伍配置补齐（只补空的，不覆盖已识别的）。

```
修复前: switch slot 2 (no model data, first living)
修复后: switch slot 2 (音速犬 dmg 385 taken 242)
```

### 4. 未知头像从没被利用（`feat(portrait)`）

```
FOE 换人 403 次 → HUD 认出 187 (46%)、立绘 51 (13%)、未知 182 (45%)
```

那 45% 躺在 `_unknown_*.png` 里没人管。

盘点：40 张未知头像里 17 张能被 620 类模型高置信识别，
识别出的名字**全部在库里**。

自动标注（置信 ≥0.90 + 名字在库 + 同名最多 3 张）：

```
模板库 84 → 96 张（+14%）
未知样本 41 → 29 张
```

### 5. 测试数据污染特性反查（`7b2ed96`）

```
FOE PANEL timing: ability 5.3s, total 17.3s (trait_only=False)
FOE SCAN -> 喵喵 特性=氧循环 属性=["草"](conf=low) (19.6s)
```

根因链：特性「氧循环」9 个候选里有 4 个是**测试数据**
（测试喵喵1/2、被克制测试喵喵、抵抗测试喵喵），属性不同
（草/冰/龙）把 `best_conf` 从 high 拉成 low → `enough=False`
→ 又跑整块 OCR（+12 秒）→ 吃掉一个回合。

修：清掉 14 只测试精灵（全部 implemented=0，从没在实盘出现过）；
`enough` 判据加"属性一致也算够用"。

```
清理前: 9 候选 → conf=low  → enough=False → 19.6s
清理后: 4 候选 → conf=high → enough=True  → ~5s
```
