# 感知层身份识别：立绘通道区域定位修复

**版本**：`ui-m72`
**日期**：2026-11-21
**前置**：`ui-m71`（标注修正，我方 94.7% / 敌方 85.6%，高置信 96.6%）

---

## 一、问题陈述

实机测试发现：`portrait_onnx.predict_region()` 在真实对战帧上置信度 **0.00**，
UI 显示"未知"。上轮结论是"立绘区域是硬编码对战镜头坐标，非对战视角抓纯背景"。

**这个结论只对了一半。** 真正的问题更严重：

`config/portrait_region.json` 里的百分比框：

```json
"foe":  {"x": 0.645, "y": 0.355, "w": 0.075, "h": 0.195}
"self": {"x": 0.225, "y": 0.55,  "w": 0.09,  "h": 0.15}
```

框的是**会在场地里走动的 3D 精灵模型**，不是固定 UI 元素。

---

## 二、诊断证据（全部实测）

### 2.1 区域画在整帧上

用 `LAYOUT_*.png` 在 `logs/shot/*.jpg` 上画出两个框：

| 帧 | REG-self 框住 | REG-foe 框住 | 绿框(HUD) 框住 |
|---|---|---|---|
| 233445 | 我方精灵的**尾巴/身体中段** | 敌方精灵**头部偏下** | 左上/右上 HUD 头像 ✓ |
| 233747 | 我方精灵**后腿** | 敌方精灵**耳朵边缘** | 同上 ✓ |
| 234212 | **人物 NPC 的腰** | 敌方精灵**翅膀** | 同上 ✓ |

3D 精灵会走动、会转身、会被 NPC 遮挡，所以同一个百分比框
在不同帧里框到的东西**完全不同**。

### 2.2 三通道准确率对比

同一批帧，`_fit` 到基准 2560×1600（模拟运行时 `grab_client`），
真值来自帧内名字条肉眼读取：

| 通道 | 准确率 | 命中时置信 | 说明 |
|---|---|---|---|
| A. `region()` 立绘框 | **0/8 = 0%** | 0.52~0.99 随机 | 框住的东西每帧都变 |
| B. HUD 头像紧框 | 5/8 = 62% | 0.56~1.00 | 紧框偏了一点 |
| C. HUD 头像 + margin=10 | **6/8 = 75%** | 多为 1.00 | **最佳** |

原始 1280×800 帧上 A/B/C 都只有 12% —— 因为分辨率只有基准的 1/4，
ONNX 输入被 Lanczos 放大后细节全糊。**运行时 `grab_client` 已 `_fit`，
所以线上真实水平是 C 的 75%，不是 12%。**

### 2.3 具体错例（`_fit` 后，HUD+margin 通道）

| 帧 | 侧 | 真值 | 预测 | 置信 |
|---|---|---|---|---|
| 233445 | foe | 石冠王蜥 | 石冠王蜥 | 1.00 ✓ |
| 233747 | foe | 彩蝶鲨 | 蓝蝶鲨 | 0.52 ✗（同族近似种） |
| 234212 | foe | 帕帕斯卡 | 龙息帕尔 | 1.00 ✗（**高置信错误**） |

`龙息帕尔` 这一例说明：**即使是 HUD 头像通道，高置信也会错**。
所以不能只看置信度，必须保留属性硬约束和防抖。

---

## 三、决策

### 3.1 停用 `region()` 立绘通道（核心决策）

理由：**0/8 准确率，且置信度 0.52~0.99 随机分布**。它现在以
`ONNX_MIN = 0.92` 的权限参与 `identify_fused()` 决策，命中时会把
正确的 HUD 结果覆盖成错的。

不是"改坐标"能解决的 —— 3D 精灵会走动，任何固定百分比框都不可靠。

**做法**：`predict_region()` 保留接口（测试和 `--compare` 还在用），
但改为**默认走 HUD 头像框**，`region()` 降级为显式开关。

### 3.2 HUD 通道改用 margin=10

实测 B(紧框) 62% → C(margin) 75%。`SEARCH_MARGIN` 本来就是为此设计的
（模板匹配要滑窗空间），ONNX 也跟着用带 margin 的裁剪更稳。

### 3.3 保留属性硬约束与防抖

`龙息帕尔 1.00` 证明高置信不可信。`foe_ident` 的属性否决 + 连续 2 帧
防抖必须保留，不能因为"HUD 通道更准"就放开。

## 四、实施步骤

1. `portrait_onnx.py`：
   - 新增 `hud_crop(screen, side)` —— 按 `portraits.*_box_for(margin)` 裁
   - `predict_region()` 默认走 `hud_crop`，`source="hud"` 可切回 `region`
   - 更新模块 docstring（删掉"喂 HUD 头像会输出 000无"的错误结论）
2. `config/portrait_region.json` 加 `"enabled": false` 标记
3. 新增 `src/test_portrait_region.py` —— 锁定"region 通道默认不参与"
4. `docs/IDENT_LIVE.md` 补这一节
5. 跑全部测试

## 五、验证标准

- `predict_region(screen, side)` 返回结果与 `PO.predict(hud_crop)` 一致
- `region()` 显式启用时才走旧路径
- 26 个测试脚本全过
- `portrait_calib.py --compare` 不受影响（它直接调 `predict()`）

---

## 六、不做的事

- **不改 `portrait_region.json` 的坐标值**。3D 精灵会走动，改坐标只是
  换一批帧碰运气，不是修复。
- **不删除 `region()` 函数**。`portrait_calib` 和 `--selftest` 还在用，
  且以后可能用目标检测（YOLO）替代固定框。
- **不提高 `ONNX_MIN`**。门槛已经 0.92，问题不在门槛而在输入框。
