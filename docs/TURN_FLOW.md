# 回合流转：为什么会出现"卡住不出招"和"第二手很久"

本文记录 2026-11-20 20:54~21:26 实测的那两次卡顿，结论都来自 `logs/bot_stdout.log`
和同刻的 `logs/shot/*.jpg`，不靠猜。

## 1. 卡死 5 分钟：0 能量时永远不按 F

### 现象

```
21:14:33 T5   SKILL 4 (best affordable dmg 105 (green)) ... lit=0111
21:14:33 之后  5 分钟，日志里只有 40 条
21:14:38 GATE energy held: not my turn yet
21:19:30 GATE energy held: not my turn yet
```

同刻截图（`logs/det2/full_now_small.png`）：

- 我方 音速犬 366/366，能量 `★0/10`，6 个能量点全暗
- 四张卡 **全部灰**（吞噬 ★6/50、力量增强 ★1、跳落 ★3/80、火云车 ★5/185）
- 没有倒计时数字

### 根因

聚能（F）的闸门是：

```python
if action[0] == "energy" and not st.get("countdown"):
    self._gate(now, "energy held: not my turn yet")
    return
```

`countdown` 是那个大白数字。它 **会闪、而且有的模式根本不画**：

| 时间 | 动作 | cnt |
|---|---|---|
| 21:10:59 | T1 SKILL 4 | 0 |
| 21:12:57 | T1 SKILL 1 | 0 |
| 21:13:39 | T2 SKILL 3 | 1 |
| 21:14:13 | T4 ENERGY F | 1 |
| 21:14:33 | T5 SKILL 4 | 0 |

技能键不看它，所以技能照常出；**只有 F 被它挡着**。0 能量时唯一能推进回合的
就是 F —— 于是死锁。而"卡住看门狗"当时写了：

```python
if st["battle"]:
    self.last_progress_at = now     # 只要在战斗里就算"有进展"
```

战斗里永远不会触发，兜不住。

### 修法

1. F 的判据加一条硬信号：**技能栏画着 + 四张卡全灰 + 能量点 <= 1 = 我的回合且没能量**。
   这时按 F 顶多被动画吞掉一次，不按就是永远卡住。
   （能量点读数可用时必须用它二次确认：能量 >= 2 却四张卡全灰是识别异常，
   乱按 F 会白送一回合。）
2. 看门狗改成按**决策状态指纹**计进展（我方/对方血量、四张卡的文字、lit 位）。
   40 秒一点没动 = 真卡住，按 F（有亮卡就按最靠前的亮卡）。
3. 战斗内不再走"按 ESC 兜底"那条老看门狗（对面可能只是慢，ESC 会开菜单）。

实测重启后第一手就恢复：

```
21:23:29 GATE F without countdown (bar up, no card affordable)
21:23:29 T1   ENERGY F (nothing affordable, gather energy) ... lit=0000
21:23:45 state battle=True bar=True me=57.4 foe=84.9      <- 对面打过来了，回合推进
21:23:46 T2   SKILL 3 ...
```

## 2. "第二次放技能很久"：面板扫描吃掉了下一手

### 现象

```
21:12:57 T1   SKILL 1
21:13:02 FOE SCAN -> opening panel
21:13:04 FOE PANEL open in 1.23s
21:13:24 FOE PANEL timing: ability 10.6s, total 20.4s (trait_only=False)
21:13:26 FOCUS LOST - click 1840,1505 dropped
21:13:28 FOE SCAN -> 乌拉? lv55 特性=恶魔的晚宴 属性=["幽","冰"] (25.6s)
21:13:39 T2   SKILL 3
```

T1 → T2 隔了 42 秒，其中 25.6 秒是扫面板。

### 根因

`_maybe_scan_foe` 不看时机，遇到未知对手就立刻点开面板；而面板链路是
"点头像 → 特性 OCR → （特性没定出属性时）整块面板 OCR → 关面板"，
一次 OCR 在这台机器上 3~7 秒，两次就是 20 秒。

### 修法

| 项 | 之前 | 现在 |
|---|---|---|
| 触发时机 | 任意时刻 | 只在刚出完手 12 秒内、且倒计时没出现 |
| 每场次数 | 3 | 2 |
| 特性 OCR | 窄条 110px → 260px（两次，且随布局切掉字头） | 标签那一行横带，**一次** |
| 特性读不出时 | 退回整块面板 OCR（+6~10s） | 只读顶部名字条（~1.5s） |
| 未入库特性 | 白读 | 落盘 `logs/unknown_traits.jsonl` |

横带裁剪（实测两种面板布局都一次读全，2.8~3.6 秒）：

```
panel_210501  badge=(35,754) -> ['上锁','特性','敌方本回合使用']
panel_211304  badge=(30,702) -> ['恶魔的晚宴','特性','主动击败敌方精！']
```

> 早先试过的窄条（110/170/260px）在两种布局之间 **不能兼得**：
> 170px 在第一块面板读得出、在第二块只剩 '晚宴'；200px 在第二块正常、
> 在第一块直接返回空。横带把"名字+描述"一起交给检测器，反而稳定。

### 附带修掉的误判：`is_open` 把训练家的白衬衫当成面板

21:26:19 那次扫描的实际 dump（`logs/panel_212619.png`）根本不是面板，是
对面训练家的大特写。旧判据是"整屏中间找大白块，阈值 6%"，白衬衫过了。
后果是：不点开面板、直接对着场景 OCR 白花 6.7 秒，最后还点了一次关闭位置。

改成在 `PANEL_BOX` 里要求"最大白连通域 >= 15%"：

| 帧 | 白占比 | 最大白块 | 判定 |
|---|---|---|---|
| panel_210501（上锁） | 0.195 | 0.185 | 面板 |
| panel_211304（恶魔的晚宴） | 0.200 | 0.193 | 面板 |
| panel_211401 | 0.201 | 0.194 | 面板 |
| panel_212619（训练家） | 0.115 | 0.108 | 不是面板 |

## 3. "火云车伤害最高却放了吞噬"— 这次不是 bug

同刻截图能对上账：

```
卡1 吞噬   ★6  50   lit=0   (能量 3 < 6)
卡2 力量增强 ★1      lit=1
卡3 跳落   ★3  80   lit=1
卡4 火云车 ★5 185   lit=1/0 视能量
```

21:23:46 那手 `lit=0110`、能量 `★3/10`，所以可放的只有卡 2、卡 3；
选中卡 3（跳落 80）是**正确**的，火云车 5 费放不出来。
卡槽映射用的是**纵向点阵**（按 y 排序，卡片是斜向堆叠的），不是按 x，
所以 `SKILL 3` 确实是第三张卡 —— 截图逐张核对过。

要判断"是不是又选错了"，看 `logs/turns.jsonl` 里同一行的 `lit` 与 `v`：
`v` 最高但 `lit=False` 的那张是**真的没能量**，不是误判。

## 4. 收尾：大世界里连点 42 次"推进"

比赛结束后游戏回到大世界（21:28:58 结束，21:29:05 起）。`_idle_tick` 的
"推进 splash" 兜底会在认不出的画面上点屏幕中下方，而它的上限 `advance_count`
被**屏幕指纹**每轮清零：

```
21:29:05 .. 21:31:11  advance splash (click 1) × 42
```

每一条都是 "click 1" —— 计数从没到过 8。原因是 8x6 灰度指纹太敏感，
大世界的水面/云/草丛/待机动作每帧都不同；而点在地面上会**让角色走过去**，
正是"点着点着走进大世界回不来"的老问题。

修法：

- 指纹降到 4x3、量化 `/32`（整屏换页仍能分开，场景微动分不开）
- `advance_count` 不再被指纹清零，改成**每场一发的预算**（12 次）
- 实测重启后：

```
21:34:57 advance splash (click 1)
21:35:08 advance splash (click 5)
21:35:16 advance splash (click 8)
21:35:28 advance splash (click 12)
21:35:30 advance cap reached on an unrecognised screen - stopping blind clicks
```

12 次够用：实测正常的"结算页→升段页→大厅"链条是 11 次点击。

> 仍未解决：大世界没有"回到 PvP 大厅"的路径。机器人只会待在原地（不再乱点），
> 需要人工把它带回大厅。这是既有边界，不在本次修复范围内。
