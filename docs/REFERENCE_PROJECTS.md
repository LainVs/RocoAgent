## 二、已定案的三件事（都是交叉验证过的）

### 2.1 面板公式：两份独立实现**代数等价**

```
9178   HP   = round((sv*1.7 + iv*0.85 + 70) * nature + 100)
       非HP = round(round(sv*1.1 + iv*0.55 + 10) * nature + 50)
roco-cal 60 级 5 星展开后完全相同（star=5 时 iv 内部 ×6、努力值 50/100）

共同怪例：种族值 105、个体 0、无性格 → 非 HP 少 1 点（float32 漂移）
         9178 用 floor，roco-cal 显式 `final_attr -= 1`，两边独立复现
```

四只实测血量全部命中：

| 精灵 | 种族值 | 个体 | 性格 | 模型 | 实测 |
|---|---|---|---|---|---|
| 音速犬 | 85 | 60 | 无 | 366 | 366 |
| 冰钻布鲁斯 | 73 | 60 | 无 | 345 | 345 |
| 寂灭骨龙 | 120 | 60 | +生命 | 490 | 490 |
| 巨鼓象 | 130 | 60 | +生命 | 510 | 510 |

> 以前写的"公式不可信、必须实测"是误判：前两只是没点满 HP，后两只是生命性格 +20%，
> 巨鼓象还牵出我们库里一个占位值（66 → 130）。

### 2.2 克制合成规则：三方一致

```
克制相加：被 1 个属性克 ×2，被 2 个 ×3（不是 ×4）
抵抗相乘：被 1 个抵抗 ×0.5，被 2 个 ×0.25
一克一抗 ×1
```

出处：9178 `getTypeEff`、roco-cal `ele_advantage.py`、loyshowdown（实机 215 验证）。

**我们的 `dmg_calc.MULT_SET` 原来是 (0.5, 0.75, 1.0, 2.0)，是错的**（按 `battle_config`
的字段名猜的）。已改为 **(0.25, 0.5, 1.0, 2.0, 3.0)**。

### 2.3 18×18 克制表：我们的库与他完全一致

按名字对齐后 **324/324 一致**（按 id 对齐会误报 153 条，因为我们的 id 是宝可梦式顺序、
roco-cal 是自定义枚举）。
