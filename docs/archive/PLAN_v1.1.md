> v1.0 已打 tag。本文档是下一阶段的设计与排期，每个模块都能独立验收，
> 不通过就不接入，保证"每个优化调控好不打架"。

### 从截图里新确认的三件事
1. **己方血量是精确数字**（417/417），不只是百分比 → 可以反推对面最大 HP。
2. **技能卡上的数字就是实际伤害**（含本系加成与克制，不含防御）→ 我们打出去的伤害不需要估。
3. HUD 上有**属性徽章**（单属性 1 个、双属性 2 个），我方对面都有 → 对面属性可直接读，
   也可以用伤害数字交叉验证。

## 二、三个核心创新点（都建立在"数字可见"上）

### 1. 用伤害数字反解对手属性（不用 OCR、不用猜）
同一回合 4 张卡显示 4 个伤害数字。设卡 k 的威力 `P_k`、属性 `t_k`、本系加成 `S_k`：

```
D_k / P_k = S_k × mult(t_k, 对手属性组合)
```

四个等式、四个未知的 `mult`，直接解出对手对各属性的倍率向量，再与 18 属性的
克制表比对，取最可能的属性组合（含双属性 324 种组合）。多回合继续累积证据（贝叶斯）。

> 这和用户之前的要求一致：**不信任 OCR 名字，用结构化信息（伤害/克制/徽章）识别**。

### 2. 借宝可梦的 TKO/TTD 竞速，做"该不该换"的期望值判断
宝可梦成熟做法：
- **TKO**（turns to KO）：我几回合能打死对面
- **TTD**（turns to die）：对面几回合能打死我
- **先手判定**：速度 + 优先级，决定谁先动
- **换人惩罚**：换人这回合白挨一下

规则化决策：
```
若能一击必杀 且 我先手           -> 直接打，不换
若 TTD <= 1 且 TKO > 1          -> 换/奶，除非换了也活不过一回合
若 TKO <= TTD                   -> 对攻
否则                             -> 换人，按换入后的 TTD/TKO 选最佳
```

### 3. 对位数据库：把每局经验变成先验
宝可梦的"使用率统计"思路搬到我们自己的对局上：

```
matchup(我方精灵, 对面精灵) -> 场次/胜负/平均承受伤害/对面最常用技能分布
```

- 对面技能分布 → 算**期望 incoming**（而不是最坏情况），换人估值更准
- 我方技能在该对位下的**实际效果**（伤害/耗能/是否击杀）→ 技能选择用 bandit 探索
- 先验 + 当回合观测 → 在线更新（简单贝叶斯，不用重模型）

## 三、模块划分（互不重叠，可并行）

| 模块 | 文件 | 依赖 | 验收 |
|---|---|---|---|
| A 数据层 | `src/rocodata.py` | 无 | 能按 id 查种族/技能/克制；单测覆盖 |
| B 伤害模型 | `src/dmg_calc.py` | A | 用截图 4 张卡的数字校准，误差 <5% |
| C 对手建模 | `src/foe_model.py` | A,B | 从 4 个伤害数字反解属性，命中率 ≥80% |
| D 对位数据库 | `src/matchup_db.py` | 无 | 从 turns/rounds/results 导入，查询 <10ms |
| E 策略 v3 | `src/policy_v3.py` | B,C,D | 可解释日志：每个候选动作给分和理由 |
| F UI 面板 | `ui/` + `src/roco_ui.py` | D | 浏览器看状态/日志/胜率/对位表/标注头像 |
| G 感知修复 | `robot.py` | 无 | result 误判、换人误判、能量语义 |

### 依赖顺序
```
A -> B -> C -> E
D ----------> E
F 独立
G 独立（不碰 B/C/E 的文件）
```

## 四、执行排期

**第 1 步（本次）**
1. `A + B`：先把数据层和伤害公式做出来，并用截图校准
2. `D`：对位库 + 从历史日志导入（先有数据再看策略）
3. `F`：UI 骨架（状态、日志、胜率、对位表、头像标注）
4. `G`：三个已确认的 bug（result 误判、换人误判、能量语义）

**第 2 步**
5. `C`：属性反解（需要 B 校准后的公式）
6. `E`：策略 v3，先影子模式（只记日志不执行），对比 v1.0 的动作

**第 3 步**
7. 影子模式跑够样本后，按胜率决定是否切换 `decide()` 到 v3
8. bandit 探索开关（默认关，逐步放开）

## 五、风险与回退

| 风险 | 处理 |
|---|---|
| 伤害公式与游戏不一致 | B 的验收标准是和卡片数字对不上就不许上线；C/E 全部只读影子模式 |
| UI 影响机器人 | 独立进程、只读日志与 SQLite（WAL 模式），不碰 robot 进程 |
| 改动打架 | 每个模块独占文件；robot.py 只由 G 和最终接入改动，接入点单一 |
| 能量语义判断错 | 先用历史帧验证再改 energy.py，改前保留旧读数做对比日志 |
| 策略变差 | v3 先影子运行，胜率对比达标才切换；保留 `--policy v2` 开关 |

## 六、成功指标

- 对位库覆盖：≥30 场、≥15 种对手精灵
- 属性反解准确率：≥80%（以徽章/已知对局人工核对）
- 决策可解释率：100%（每条动作都有 why）
- 胜率：v1.0 基线（37 场）→ 目标 +10 个百分点
