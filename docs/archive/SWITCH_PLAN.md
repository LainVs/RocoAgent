## 0. 结论先行

1. **现在的换人不是一个决策，是四条硬触发 + 盲选目标。**
   `_switch_advice()` 只在四种情况返回"换"（能秒 / 被秒 / 打不动 / 属性劣势），
   而"换谁"永远交给 `next_switch_slot()`——它按**一个会错位的槽位表**挑"血最多"，
   所以"换回去再被秒"是必然的，不是运气差。
2. **关键的缺失信息只有一项：后排是谁、还剩多少血、还剩多少能量。**
   这些**全都在换人面板上**（`logs/panel5.png` 已经拍到：每行有头像、血条、★N 能量）。
   目前代码只用了"行的位置"和"血条填充率"，**没有读头像、没有读 ★N**，所以它不知道换上来的是谁。
3. **建议分四步走**：先修崩溃（S0）→ 修帧内逻辑错误（S1）→ 加面板读取，只记日志不决策（S2）
   → 判据上线并灰度（S3）。**不要**一上来就换算法，否则没有可信数据判断对错。

## 2. 现有决策链（代码级）

```
Perc.observe()                        # 每 0.12 s 一帧
  └─ st = {battle, bar, my_pct, foe_pct, energy, skills[4]}
        │
        ├─ _decide_v2()  ── policy_v2.decide()
        │     └─ 它的 switch 建议被 **明确忽略**（robot.py:2010 "v2 wanted SWITCH -> ignored"）
        │
        └─ _switch_advice(st)          # robot.py:2598，唯一的主动换人入口
              ├─ ① 能一击必杀           → 不换
              ├─ ② 对面最凶一击 >= 我血  → 换
              ├─ ③ 每手伤害 < 15% 对面血 → 换
              ├─ ④ 全被抵抗且伤害 < 35%  → 换
              └─ 目标 = next_switch_slot()
                    └─ 按 slot_hp[槽位] 挑血最多（默认未知=100%）
```

### 2.1 为什么 `slot_hp` 会错位（这是循环的第一个根因）

- `cur_slot` 是**行号**，不是队伍槽位：`_try_switch()`（robot.py:3834 起）点了第 N 行就直接
  `self.cur_slot = action[1]`。
- 但换人面板**不显示在场的那只**。所以"第 3 行"在 6 只全活时是 4 号位，在死了一只之后可能是 5 号位。
- 力竭换人这条路径**根本没有更新 `cur_slot`**（只有主动换人那条更新了，robot.py:3250）。
  → 换完之后，HUD 上**新上场这只的血量**被写进**上一只**的槽位（robot.py:1860），
    于是 `next_switch_slot()` 认为"那只残血的还有 88%"，下一次就把它换回来。

> 一句话：**用会漂移的槽位号当主键，等于记错了谁还有多少血。**

### 2.2 为什么"换上去就被打残"（第二个根因）

- 判据 ② 只看"我会不会被秒"，**完全不看换上来那只扛不扛得住**。
- 换人当回合对面白打一手（SWITCH_B 假设 A1），所以换入者天然要吃一次最凶的伤害。
- 判据 ② 满足时，当前血通常只剩 10~20%，而换入者的血量**未知**（默认 100%）——
  代码实际上是在赌。

### 2.3 没有迟滞

- 没有任何"刚换过就别再换"的限制。`switch_streak` 只写进 `ctx` 给 policy_v2 当特征（robot.py:2799/3083），
  **不参与否决**。
- 所以在 15 秒内连续两回合触发是允许的。

### 2.4 能量读了但没用

- `energy.py` 每帧读 pips（`st["energy"]`），但 `_switch_advice()`、`decide()`、`policy_v2.decide()`
  都**没有用**它做换人判断（policy_v2 里 `w_energy` 只值 0.03 分，且 switch 分支被忽略）。
- 你提到的"残血要不要留场"本质是：**它还有没有能量打出一手**。
  一个 3% 血但有 7 点能量、能先手带走对面的精灵，和一只 3% 血 0 能量的精灵，处理方式完全不同。

### 2.5 后排信息几乎没有进入决策

- `bench_state()`（robot.py:2017）只给 policy_v2 名字，血量直接写"满血"（`hp=mx`），
  能量写死 10——**假数据**，而且 policy_v2 的换人又被忽略。
- `_pick_switch_slot()`（强制换人）用 `bench_names.get(行号)` 找名字（同样会错位），
  再用 `worst_incoming()` 取**整个技能池的最坏一击**（比真实配招悲观得多）。

## 4. 博弈模型（可执行版）

完整推导在 `docs/SWITCH_B_ALGO.md`，这里只保留**能在一帧内算完**的部分。

### 4.1 竞速数（核心）

```
n = ceil(h_b * H_b / d_max)        # 还要几手打死对面
r = ceil(h_a * H_a / D̄)            # 还能挨几下
Φ = r - n                          # 竞速盈余；>0 表示我赢这场赛跑
```

- `n = 1` → 这手能击杀。
- `r = 1` → 下一手必死。
- `Φ > 0` 且先手 → 只要不被换人打断，站桩就能赢。

### 4.2 判据表（按优先级）

| 编号 | 条件 | 动作 | 依据 |
|---|---|---|---|
| **K** | `d_max >= h_b·H_b` 且（我先手 或 `D̄ < h_a·H_a`） | **绝不换**，出手 | void/引理 2 |
| **S** | `r <= 1` 且后排没有 `h_j > D̄(b→j)` 的 | **送掉**，留场打最后一手 | §2.4 NO_ESCAPE |
| **S'** | `r <= 1` 且存在能扛住的 `j` | 换 `j`，但要求 `Φ_j - 1 > Φ_a` | §2.4 |
| **D** | `r <= 3` 且 `d_max/(h_b·H_b) < 1/r` | 换（竞速输） | §2.5 |
| **B** | `Φ_j - 1 >= Φ_a + 1`（换人白送一手，要赚回 ≥1 手） | 换 | §2.6 |
| **E** | 一张伤害卡都放不出（`lit` 全假）且 `e_a < 3` | 换 > 聚能 | §2.7-E |
| **H** | 距上次换人 ≤ 1 手 | 不换 | 迟滞（§7.2 R5） |

### 4.3 换谁（有了面板数据之后）

```
对每一行 j:
    hp_j, e_j, species_j = 面板读取
    dmg_j  = 该物种对本对手的理论最高伤害（pvp_engine）
    D̄_j    = 对面打它的最凶一击（模型）
    n_j = ceil(h_b·H_b / dmg_j)
    r_j = ceil(hp_j / D̄_j)
    score_j = (r_j - n_j) - 1          # 减 1：换人白送一手
    过滤：hp_j < 45% 的行直接淘汰（换上去就是送）
            e_j < 最便宜技能耗能 且 dmg_j 不高的行降权
选 argmax score_j
```

### 4.4 为什么这能打断循环

- 换入者**必须扛得住**对面的最凶一击（`r_j >= 2`），否则不换；
- 换完下一手**禁止再换**（迟滞）；
- 后排全在 45% 以下 → **关面板留场**；
- 必死时**默认送掉**，不再"换一只上来白挨"。

```
不预加载  → 加载 winrt\MSVCP140.dll (14.29) → import onnxruntime → 0xC0000005
预加载    → 加载 System32\msvcp140.dll (14.51) → import onnxruntime → OK
```

**已做**：`robot.py` 顶部预加载系统 `msvcp140.dll`；OCR 在 BLE 前预热；

## 8. 风险与回滚

| 风险 | 触发 | 处置 |
|---|---|---|
| 判据太保守 → 一局不换 | `D̄` 被高估（worst 技能池） | 用 `foe_moves` 的分布替代全池；保留一条"残血低于 12% 且后排 >70%"的硬兜底 |
| 面板读取误判 → 换错人 | 头像相似/血条标定偏 | 读不准就**不换**（fail-closed），并在日志里标 `panel_uncertain` |
| 送人策略被对手利用 | 对面读我方状态 | 送人只在 `r<=1` 且无解时用，不是常态 |
| 能量语义错 | pip 与 cost 不同量纲 | 先只用 `lit`，确认后再开 E 判据 |
| S0 未修 | 崩溃 | 所有策略改动必须等 S0 验收 |

**回滚**：所有新行为由 `config/policy_weights.json` 的开关控制（`switch_v3: false` 即回到旧逻辑），
不需要改代码回滚。

5. **验证成本**：接受"先打 10 局、每局人工看 1 分钟日志"吗？如果不接受，就只能靠影子日志，
   收敛会慢 2~3 倍。
