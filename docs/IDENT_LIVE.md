# 独立计算器的识别能力（实盘实测，2026-11-21）

> 目标：不启动机器人、不开 BLE，只读屏幕就能算出双方身份和伤害。
> 代码：`src/hud_ident.py`（读 HUD）、`src/foe_ident.py`（融合）、`src/standalone.py`（接入）

## 一、HUD 上有哪些信号

真实对局帧（2560×1600）上的布局：

```
[属性图标] [头像] 名字 ♂ 60级 [血条 162/345]
```

| 信号 | 玩家能否改 | 实测可靠性 | 定位 |
|---|---|---|---|
| **属性图标** | ❌ 不能 | NCC ≥ 0.80 时 **100% 正确**（30/30） | Hough 实测固定坐标 |
| **名字文字** | ✅ **能改（昵称）** | OCR 87%（69 帧验证） | ±4px 敏感，需滑动搜索 |
| 头像模板 | ❌ 不能 | 留一验证 Top-1 仅 **42.1%** | 敌方库 95 只 |
| 立绘 ONNX | ❌ 不能 | 静止画面 conf **0.0** | 620 类模型 |

**结论：只有属性图标和名字两条通道真正可用。**

## 二、属性图标识别

### 2.1 素材

`assets/ext/type_icons/` —— 18 张官方图标，198×198 RGBA。
来源 `chy5301/roco-kingdom-world-coverage-calc`，图标抓自 biligame wiki。
详见该目录 `SOURCE.md`（记录了两次失败尝试）。

### 2.2 坐标（2560×1600 客户区，Hough 圆检测实测）

```python
MY_ICON_CENTERS  = ((56, 98), (72, 124))      # 我方
FOE_ICON_CENTERS = ((2142, 96), (2158, 124))  # 敌方
ICON_R = 15
```

两个图标沿对角线排列，第一个左上、第二个右下。单属性精灵只有第一个。

### 2.3 匹配算法

试了 4 种方法，最后用**灰度 NCC + 旋转缩放搜索**：

| 方法 | 幻系（螺旋） | 地系（山形） | 结论 |
|---|---|---|---|
| 直接 resize + NCC | 全部挤在 0.60 | 全部挤在 0.60 | 尺度不同，废 |
| 内切圆 + 二值 IoU | 0.523（认成普通） | 0.943 | 细线条碎裂 |
| Hu 矩前 6 项 | 排第 4 | 0.16 | 螺旋不稳 |
| **灰度 NCC + 旋转缩放** | **0.56 第 1** | **0.91 第 1** | **采用** |

关键点：

1. **灰度不二值化** —— 保留 2~3px 笔画，避免螺旋碎成轮廓
2. **自适应阈值拉伸** —— 抹掉 HUD 半透明蒙层的亮度漂移
3. **图案外接框归一化到 32×32** —— 消掉 198px vs 26px 的尺度差
4. **15° 步长旋转 + 3 档缩放（1.0/1.10/0.92）** —— 图标有浮动动画，
   而且放大过程让笔画变粗（缩放 1.10 时 NCC 从 0.461 升到 0.564）

代价 165 ms/侧。

### 2.4 圆盘检测（判断这个位置有没有图标）

判据：**内圈（r<0.60）与外圈（0.85<r<1.05）的灰度均值差 > 18**。

```
我方 冰系图标       69.0
敌方 地系图标      101.3
敌方 幻系图标       70.6
我方 头像碎片       14.8   <- 唯一的非图标
```

18 与 69 之间 4 倍余量。

**不用饱和度**：幻系的淡紫底在蒙层下饱和度只有 48，会漏判。
亮度差不受蒙层影响（蒙层是乘法，内外同比缩放）。

### 2.5 门槛标定

```
NCC >= 0.80    30 个，100% 正确
NCC 0.50~0.60   2 个，0% 正确（遮挡噪声）
NCC 0.60~0.80   0 个  <- 完全空白
```

干净双峰，门槛取 **0.80**。

### 2.6 准确率

```
69 帧可验证样本：60/69 = 87%
9 帧失败全是"读不出"，没有一帧读错
  8 帧是迪莫（光系单属性，图标被头像压住，NCC 0.51）
  1 帧是音速犬（同上）
```

**读不出比读错好。** 属性错会让克制算错 4 倍，宁可返回空。

## 三、名字 OCR

### 3.1 坐标

```python
MY_NAME_BOX  = (130, 40, 260, 60)     # 我方
FOE_NAME_BOX = (2225, 50, 210, 55)    # 敌方（config.py 已有）
```

**±4px 就完全失效**：

```
(126, 36, 270, 60) -> 读出 "604"        （错，框到了等级）
(130, 40, 260, 60) -> 读出 "银月狼王"   （对）
```

所以 `read_name` 做 ±8px 滑动搜索，但**默认先试基准框** ——
OCR 一次 1~2 秒，81 组全搜要两分钟。

### 3.2 名字不能当种族名（用户指出的关键点）

> "名字其实不完全可信，排位有很多改名精灵。这就是我们机器人做特性反查的原因。"

`nickname_map` 表印证：22 条记录全是玩家昵称

```
影影绰绰        -> 3541
玲珑的妙脆角    -> 3156
黑武士          -> 3259
漆黑的冥古龙    -> 990000001
```

所以：

- 敌方名字只当**昵称键**，先查 `nickname_map`
- 未命中且与属性冲突 -> 否决
- 确认后才写入（`foe_ident.bind`）

### 3.3 我方可以用名字

我方是 `my_team` 表里**已知的 5 只**，HUD 上印的是种族名。
实测读到"冰钻布鲁斯" conf=1.0。

要求**必须命中 my_team** 才采信 —— 我方不可能出现队伍外的精灵。

比头像模板强：模板只有 4/5 覆盖，实测匹配分 0.515 还把恶魔狼认成"首领-恶魔狼"。

## 四、融合逻辑（`foe_ident.identify`）

```
1. 读属性图标 -> types（硬约束）
2. 属性过滤候选池 -> cands
3. 名字 -> nickname_map 命中 -> 确定
4. 名字恰好是种族名且属性兼容 -> 确定
5. 只剩 1 只候选 -> 确定
6. 头像模板（只在候选集内挑，>=0.85 且领先 0.06）
7. 立绘 ONNX（必须落在候选集内）
8. 都定不下来 -> 返回候选列表，绝不猜
```

### 4.1 属性用「包含」而不是「相等」

HUD 上第二个图标经常被遮挡。实测对面「仪式巨像」是 地+幻，
但只读到「地」。如果要求精确相等，候选池只剩纯地系 149 只，**正确答案不在里面**。

改成"候选的属性必须包含已读到的属性"：

```
读到 ['地']       -> 地、地+幻、地+毒… 都在候选里
读到 ['地','幻']  -> 只剩 5 只（祭礼巨像/仪式巨像/仪式之星/仪使者/首领-仪式巨像）
```

读到的属性越多池子越小，读漏了也不会把正确答案排除。

## 五、实盘验证记录

### 5.1 仪式巨像（幻+地）

```
me   = 冰钻布鲁斯  types=[冰]      conf=1.0
foe  = 仪式巨像    types=[幻, 地]  conf=1.0
候选  = 5 只，属性全部是 幻+地 ✓
技能卡 = 132 / 330 / 30
```

### 5.2 月牙雪熊（幻+冰）—— 暴露能力边界

```
me   = 冰钻布鲁斯  types=[冰]
foe  = 月牙雪熊    types=[冰]       <- 幻系没读到
候选  = 81 只（纯冰系）
```

幻系螺旋 NCC 只有 0.56（低于门槛 0.80），被正确拒绝。
**81 只候选 = 识别退化，但不会算错。**

同时两条辅助通道也失效：

```
头像模板 -> 卡瓦重 0.529（错，实际是月牙雪熊）
立绘 ONNX -> 咕咕鸟 0.0（置信度 0，等于瞎猜）
```

## 六、已知边界

| 边界 | 影响 | 缓解 |
|---|---|---|
| 属性图标被头像遮挡 | 该侧属性读不出 | 用包含匹配，只缩小不误放 |
| 单属性精灵第二位置被挡 | 可能多读一个 | 圆盘检测（内外圈亮度差）|
| 名字是昵称 | 不能当身份 | 查 nickname_map，未确认不采信 |
| 头像模板只覆盖 95 只 | 没见过的认不出 | 只当辅助投票 |
| 立绘 ONNX 静止画面失效 | conf 0.0 | 只当辅助投票 |
| 名字 OCR 对坐标敏感 | ±4px 全错 | ±8px 滑动搜索（默认只试基准框）|

## 七、下一步（按性价比）

1. **补更多属性的图标样本**：现在只验证了 5~6 种属性的真实帧，
   草/水/电/武/毒/翼/萌/虫/机械/普通 都没见过。
   跑几晚 PvP 攒帧即可。
2. **幻系螺旋专项优化**：0.56 距门槛 0.80 只差 0.24，
   试过 Hu 矩/二值 IoU 都不行，可以试模板融合（多角度均值）或小分类器。
3. **UI 显示候选列表**：`foe.candidates` 已经输出，
   前端显示"候选：A / B"比干巴巴的"未知"有用。

   会猜位置读出荒唐数字（实测 752，对面血量上限只有 461）。
   已在 standalone 层加合理性过滤，但根子在 perceive。
