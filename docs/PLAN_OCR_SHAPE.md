# 计划：OCR 单字错读的处置（「诋毁」读成「诉毁」）

## 现象

```
08:36:40 BAND -> 音速犬 槽3 未识别 (conf 0.50 < 0.80) raw='诉毁' vocab=4(config)
```

`tier=config` 证明两级词表生效（配置 = 借用/火云车/诋毁/闪光冲击），
但 OCR 把「诋毁」读成「诉毁」（诋 vs 诉，形近字），匹配分 0.50，被拒。

同样的在 dump 图上确认过：

```
banddump 图里清楚是「诋毁」  ->  日志 raw='诉毁'
```

## 这是真字错，不是词表问题

前面修的两层都不是这个：词表已正确（config）、ROI 已正确（图对得上）。
剩下的是 **OCR 模型本身对形近字的识别精度**。

## 三个可选方向

### A. 提高 ROI 分辨率（先做，成本最低）

现在 `read_band` 用 `fx=2.5, fy=2.5` 放大后喂 OCR。名字带高 62px
（fy1+3 到 fy1+65），2.5x 后 155px —— 而 OCR 引擎通常对
32~48px 的字高最敏感，155px 可能**过大反而糊**。

实测过 `fx=2.0` 也能读对（test_session_moves 的 fixture 用例就是 2.0）。
值得做一次 1.5 / 2.0 / 2.5 / 3.0 的扫描，用真帧选最优。

### B. 配置词表内的"近似二次确认"

配置只有 4 个词时，可以用**字级相似度**兜底：
raw='诉毁' 与配置里的「诋毁」编辑距离 1、共享「毁」字 ->
如果 4 个候选里**只有一个**满足"共享至少 1 字 + 长度相同"，
且第一候选明显领先，就采纳。

风险：4 个候选词如果都很像，会误配。必须要求**唯一性**。

### C. 三帧投票（最稳，成本最高）

同一槽位连读 3 次，取出现 >= 2 次的 raw。
实测「诉毁」若连续 3 次都读成一样，那就是稳定误读，投票也没用。
所以这条对"随机抖动"有效，对"系统性形近误读"无效。

按实测数据看，`诉毁` 在同一场连读 3 次都一样 —— 是**系统性**误读，
C 方向无效。

## 建议顺序

1. **先做 A**（放大倍数扫描）—— 可能直接解决，且无安全风险
2. 不行再做 **B**（唯一性约束下的近似匹配）
3. C 不做（实测无效）

## 验收

- 「诋毁」能读出（conf >= 0.80）
- 不引入新误配：配置外的词仍被拒
- 用真帧 fixture 做回归，不依赖在线 OCR 的随机性

## 注意

本轮 BAND 已能覆盖多数场景（银月狼王 3/3、冰钻布鲁斯 4/4 全中）。
单字错读是**长尾问题**，不应为它牺牲已有的安全性。优先级低于
"确认整体链路无回归"。
