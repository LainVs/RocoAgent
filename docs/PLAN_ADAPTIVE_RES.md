# 计划：自适应分辨率（HUD 锚点布局）

> 2026-11-21 · 触发：用户把游戏从 2560×1600 调到 2048×1536 后，识别全废

---

## 一、其他项目怎么做的（已核查）

| 项目 | 拿状态的方式 | 有没有做分辨率自适应 |
|---|---|---|
| rocom-helper | **抓包**（监听 8195 端口解析协议） | 不适用（不看屏） |
| roco-cal | 纯计算器 | 不适用 |
| nrc-ai | 离线模拟 | 不适用 |
| rocom-data | 只有几张固定 UI 模板（`start_challenge.png` 等） | **没有**，模板是死的 |
| rocoarena | 网页数据 | 不适用 |

**结论：没有现成可抄的。我们得自己建。**

不过我们**已经有核心零件** —— `src/matdet.py` 里：

```
find_bars(roi, ...)      # 找血条（颜色 + 形状）
find_slabs(roi, ...)     # 找条状底板
pick_pair(bars_l, bars_r)# 左右血条配对
measure_fill(...)        # 条内填充比例
```

这些是**不依赖固定坐标**的检测器，正是自适应布局的锚点来源。

## 二、今天暴露的两个问题（都已实测）

### 2.1 DPI 缩放（已修，commit 62f0a80）

本机 200% 缩放。进程未声明 DPI 感知时：

```
GetWindowRect -> (539,  8, 1037x804)     逻辑坐标
mss 抓屏                              -> 物理像素
                                        => 差 2 倍
```

`robot.py` 有 `SetProcessDpiAwareness(2)` 所以能打；
`standalone`/`ui_server` 没有所以一直瞎。**已修**，修完名字 OCR 立刻正常：

```
敌方名字 -> 里拉   (conf 1.0)
我方名字 -> 音速犬 (conf 1.0)
```

### 2.2 非等比拉伸把图标拉变形（未修）

`grab_client` 把任意客户区尺寸**拉伸**回基准 2560×1600：

```
2048x1536 -> 2560x1600    x 放大 1.25，y 放大 1.042
```

宽高比例不同 → 图标被**非等比变形** → 形状匹配失效。
实测属性图标最佳匹配只有 **0.59**（门槛 0.80），名字条因为够宽容错才侥幸通过。

## 三、方案：原生抓取 + 锚点相对布局

### 3.1 核心原则

**不拉伸。** 在客户区原分辨率上工作，所有框按**相对锚点**的偏移给出。

HUD 在 UE4 UMG 里是贴边锚定的，所以：

```
左上 HUD（我方）   锚 (0, 0)         -> x' = kx * x,           y' = ky * y
右上 HUD（敌方）   锚 (W, 0)         -> x' = W - kx*(BW - x),  y' = ky * y
左下技能栏         锚 (0, H)         -> x' = kx * x,           y' = H - ky*(BH - y)
右下操作按钮       锚 (W, H)         -> 两个方向都反着算
```

其中 `kx = W / BW`、`ky = H / BH`（BW/BH = 基准 2560/1600）。

**注意**：`kx ≠ ky` 时说明宽高比变了。这时**只能按 ky（高度比例）缩放，
再按锚点贴边**，不能用 kx —— 因为 UMG 的 DPI 曲线是按视口高度算的。

### 3.2 运行时校验（关键）

光算不够，必须**用检测器验证**：

```
1. 用 matdet.find_bars 在整帧里找左右血条
2. 找到 -> 用血条真实位置反推 (kx, ky) 和锚点偏移
3. 找不到 -> 退回公式计算值
4. 两者都失败 -> 认为"这一帧没有 HUD"，返回空（而不是瞎读）
```

这样即使以后游戏换了 UI 布局，只要血条还在，其余元素就能跟着走。

### 3.3 为什么必须先做血条锚定

血条是 HUD 里**唯一**同时具备三个特征的元素：

- 颜色鲜明（绿/黄/红渐变 + 灰度底板）
- 形状规则（细长矩形，宽高比 10:1 以上）
- 左右各一条，位置固定对称

名字条是白字压半透明底，属性图标是 26px 小圆，都不如血条好找。

## 四、实施步骤

### Step 1（已完成）DPI 感知
`winio._declare_dpi_aware()` —— 所有进程统一物理坐标。

### Step 2 锚点布局表

新建 `src/layout.py`：

```python

# 每个框： (锚点, 基准坐标, 说明)
# 锚点: TL / TR / BL / BR

    "skill_col":    ("BL", (250, 480, 780, 1520)),
    "action_btn":   ("BR", (2150, 1440, 360, 140)),
}

def to_client(name, client_w, client_h, base=BASE):
    """基准坐标 -> 当前客户区坐标（按锚点 + 高度比例）"""
```

### Step 3 原生抓取

`Screen.grab_client` 增加 `normalize=False` 模式：
- 不做 `_fit()` 缩放回基准
- 直接返回客户区原尺寸图

调用方（hud_ident / foe_ident）改用 `layout.to_client()` 拿框，
在原尺寸图上裁剪 —— 不再有变形。

### Step 4 检测器校验

`src/layout.py` 加 `calibrate(frame)`：
- 跑 `matdet.find_bars` 找血条
- 用真实位置修正 `(kx, ky)` 和锚点偏移
- 把结果缓存（同一分辨率下不变）

### Step 5 回归测试

`src/test_layout.py`：
- 2560×1600（基准）下 `to_client` 是恒等映射
- 2048×1536（4:3）下左右 HUD 各自贴边、不被拉伸
- 1920×1080（16:9）同上
- 宽度极端（如 800×1600）不产生越界框

## 五、不做的事

| 项 | 原因 |
|---|---|
| 针对每种分辨率存一套坐标 | 组合爆炸，且用户随时会改 |
| 用 OCR 找名字条当锚点 | OCR 5~7 秒，太慢；血条检测 <20ms |
| 强行把游戏拉回 2560×1600 | 用户可能在低配机/窗口模式下玩，应该适应而不是强制 |
| 缩放模板去匹配拉伸后的图 | 变形是非等比的，缩放补不回来 |

---

## 六、已知风险

1. **4:3 下 UMG 可能裁切**：2048×1536 比 16:10 窄，右侧 HUD 可能被裁掉一部分。
   如果血条都找不到，说明游戏本身在这个分辨率下显示不全 —— 那得建议用户换回 16:10。
2. **技能栏在左下角**，4:3 下可能与操作按钮重叠，需要实测确认。
3. `matdet.find_bars` 目前只在 2560×1600 的帧上验证过，
   其他分辨率下的参数（`min_w_frac` 等）用的是比例，理论上通用，但需实测。
