## 一、两边是什么

| | RocoAgent（我们） | 洛克PVP助手（它） |
|---|---|---|
| **形态** | 全自动对战机器人（截图→识别→决策→硬件 HID 出招） | 半自动辅助 HUD（抓包→协议解析→屏幕叠加显示） |
| **数据来源** | 屏幕截图 OCR/模板/ONNX | 网络抓包（0x4013 AES 解密）+ 官方 PAK 解包数据 |
| **自动化** | 完全自动打完整局 | 只显示，不出招 |
| **核心难点** | 感知（看得准） | 协议（抓得住） |
| **已知短板** | 胜率 29%，我方识别 58%→84% | 不出招、链路脆（要管理员+Npcap+抓 key） |

**互补关系**：它解决了我们最难的问题（感知精度），我们解决了它没有的问题（自动执行）。

2. **新增 `src/skill_kind_official.py`** ✅
   - `official_kind()` 按效果链分类 self_buff/enemy_debuff/heal
   - **只信三类明确的**：初版把"有效果链"都标 control，会误导
     （它是纯攻击技）
   - ⚠ **复查纠错（2026-11-22 用户指出）**：此前写"岩脉崩毁效果链只是
     位置固定"是**错的**。真实语义是「**能耗固定为 4**」—— desc /
     energy_cost=[4] / 我们的库三处一致；"位置不会改变"是同族
     「主轴」的 desc，两者 `skill_feature=4` 相同被我张冠李戴。
   - 更深的问题：岩脉崩毁的 `effect_id=1079002` 在 rkpp 数据里
     **没有对应实体** —— 这类技能的效果链不完整，分类器在它们身上
     是瞎的。`skill_feature=4 & can_changed=1` 一族 8 个技能
     （不动如山/不可接触/丢冰块/乘胜追击/下注/三连星/主轴/岩脉崩毁）
     规则各不相同，不能用一个标签概括。
   - 幸好两道防线挡住实害：`classify_official_first` 只在三类明确时
     覆盖，control 一律回退旧分类（岩脉崩毁仍按 damage 评估）；
     policy_v2 的伤害评估走自算+卡面，不走分类。
   - **教训：effect 链查不到实体 = 数据不完整，必须显式标注"未知"，
     绝不能脑补语义；写进 commit/汇报的每个结论都要有数据出处。**
3. **接进决策**（✅ a1/a2/a3 链路已通）

## 四、已确认的技术事实（探测记录）

1. `skill` 实体：1655 条，`skill_result[].effect_id` 指向 `buff` 实体
   （= buff_group），其 `buff_base_ids[]` 指向 `buffbase`（含 editor_name）
2. `buffbase.editor_name` 是**语义化中文**：「物攻等级提升10」「击杀获得6能量」
   —— 这就是 buff 识别的翻译字典，编号即语义（+10/-10 对应等级±1）
3. `pet_skill.id == species_id`（3071 音速犬 13 技、3296 卡瓦重 14 技）✅
4. 官方 `skill_priority`：5=基准、>5 先手、<5 后手（推翻昨晚"脏数据"误判）
5. 官方伤害公式与我们逐位一致（122==122 验证过），仅 float32 舍入差异
