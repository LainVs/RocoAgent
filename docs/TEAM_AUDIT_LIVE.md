## 坐标校准（这一轮最大的坑）

### 踩过的三个错误

1. **换算用了错误坐标系**
   `game_cli.py click` 收的是"窗口坐标"（要减 `BASE_OFF(13,58)`），
   而我量出来的是**截图坐标**（== 客户区基准坐标，不该减）。
   结果每次偏 (10, 56) 像素 —— 用户当场看到"鼠标每次都是偏的"。

2. **靠目测/网格估头像 x**，误差 20~40px，而头像半径约 50px，
   于是"有时命中、有时落空"（槽3 连试两次都是高亮动了但面板没换）。

3. **靠图像检测找锚点**（橙色描边 / HoughCircles / 暗色峰值）全部不可靠：
   - 橙色其实是精灵自身花纹（橘色的角、爪子）
   - HoughCircles 检出间距 160/234/192/200 完全不一致
   - 暗色峰值算出的间距 198 接近但不够精确

### 最终可靠的做法

**`scripts/calib_cursor.py`（用 `GetCursorPos` 只读校准）+ 扫线验证**

校准结果（三个分布很开的点）：

```
目标截图(  80,120) -> 期望物理(1048,182)  实测光标(1050,182)  偏差(+2,+0)
目标截图( 640,120) -> 期望物理(1496,182)  实测光标(1498,183)  偏差(+2,+1)
目标截图(1200,120) -> 期望物理(1944,182)  实测光标(1946,183)  偏差(+2,+1)
```

**偏差恒定 (+2,+0)，不随位置变化** —— 证明公式
`screen = client_rect + shot * scale` 完全正确，问题从来不在公式。

`scripts/scan_slots.py` 在 y=250 上每 12px 点一次、比对右侧面板是否变化，
扫出真实槽位中心：

```
x = 174, 378, 582, 774, 978, 1170
```

6 个点每个都用"面板真的变了"验证过，`capture_team.py` 再采时 6/6 全部
`变化 > 15000 像素`。

> 注：截图里**不含系统光标**（PrintWindow 抓不到），所以"看截图上的鼠标位置"
> 这条路走不通，只能用 `GetCursorPos` 直接读。
