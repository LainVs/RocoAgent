# 计划：修复队伍配置与实际装备不一致

## 问题（2026-11-21 用户报，已确认）

用户反馈两个具体场景都"选了伤害更低的技能"：

1. **冰钻布鲁斯 vs 独角兽**：丢冰块伤害更高，却选了主轴
2. **卡瓦重**：有筛管奔流，却选了伤害最低的扬沙

## 根因：队伍配置过期，不是策略 bug

### 证据

`my_team` 表里卡瓦重配的技能：

```
升龙咆哮  power=200  cost=3  龙
冰雹      power=105  cost=4  冰
顶端优势  power=100  cost=3  草
取念      power=0    cost=0  普通
```

但卡瓦重**实际可学**（`species_skills`，44 个）里包含：

```
筛管奔流  power=80   cost=3  草    <- 用户说实际带了
扬沙      power=60   cost=1  地    <- 用户说实际带了
```

配置里**没有**筛管奔流和扬沙。

### 后果链

```
my_card_costs("卡瓦重") 读配置 -> {1:3, 2:4, 3:3, 4:0}
实际装备             -> {1:3, 2:1, 3:? , 4:?}

slot 2 的 cost 从 1 被当成 4 -> 能耗惩罚错 3 倍
```

加上 `skill_kind` 也是按配置的技能名查的：

```
配置 slot1=升龙咆哮(damage) -> 实际 slot1=筛管奔流(damage)  碰巧对
配置 slot2=冰雹(damage)     -> 实际 slot2=扬沙(damage)      碰巧对
配置 slot4=取念(copy)       -> 实际 slot4=?                 可能错
```

所以 `cost` 和 `kind` 都可能是错的。

### 为什么"冰钻布鲁斯"完全不在队伍里

`my_team` 只有 6 只：恶魔狼/音速犬/刨雪鹅/银月狼王/冥古龙/卡瓦重。
用户说队伍一直有冰钻布鲁斯 —— 说明配置从某个时间点起就与实盘脱节了。

## 修复方案

### 1. 用实盘读数反推真实装备（自动校正）

关键洞察：**卡面伤害数字 + 属性克制关系**可以反推技能。

对每只精灵：
```
候选 = species_skills 里所有 power>0 的技能
对每个候选技能 s：
    预测伤害 = damage_v2(精灵atk, 对手def, s.power, s.type 克制)
    与实际卡面读数比较
选误差最小的作为该槽位的技能
```

但这需要知道对手的防御值，且读数会抖动 —— 复杂度高。

### 2. 更可靠：让用户确认一次（推荐）

写一个交互工具，列出每只精灵的：
- 当前配置的 4 个技能
- 实盘观察到 4 个槽位的典型伤害读数

用户点选/输入实际装备的技能，写入数据库。

### 3. 最实用：从实盘读数自动匹配（启发式）

```
对每只精灵的每个槽位：
    收集该槽位所有历史读数（去重后取众数）
    对每个候选技能算"预测伤害"，找最接近的
    如果误差 < 15% 且唯一，自动写入配置
```

## 先做诊断，不急着改

在改数据之前，先搞清楚：
1. 实盘读数里卡瓦重的 4 个槽位典型值是多少？
2. 这些值对应哪些技能？
3. 队伍里到底应该是哪 6 只？

## 验收标准

1. 输出一份"配置 vs 实盘推断"对照表
2. 用户确认后写入数据库
3. 后续 cost/kind 查表正确

## 不做的事

- 不凭猜测改队伍配置（会引入新的错误）
- 不基于过期配置继续调策略参数
