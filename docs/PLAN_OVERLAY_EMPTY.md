# 悬浮窗空数据状态优化

**版本**：`ui-m75`
**日期**：2026-11-21
**前置**：`ui-m74`

---

## 一、问题（实机截图暴露）

悬浮窗在**游戏黑屏/加载中/不在战斗**时，整块面板是这样：

```
● 状态未知  [独立]  T—
┌──────────────────────────────┐
│ [寂] 未知                     │   ← 名字未知
│ ████████████░░░░   —          │   ← 血条按 0 画，百分比 —
│ —                             │   ← 血量绝对值 —
├──────────────────────────────┤
│ 我打 ×—   ⇄   打我 ×—          │   ← 克制关系全空
├──────────────────────────────┤
│ [水] 未知                     │
│ ████████████░░░░   —          │
│ 血量 —   物防 —               │
│ 性格 —                        │
└──────────────────────────────┘
   — 回合击杀 · — 回合被击杀 · 数据不足
```

**问题不在"没有数据"，而在"满屏都是破折号"。**

用户看到 12 个 `—` 和 4 个「未知」，第一反应是"这东西坏了"，
而不是"现在不在战斗"。这是**信息噪声伪装成信息**。

### 1.1 为什么会这样

`renderEmpty()` 处理的是"机器人未启动"（`/api/state` 返回 null），
文案是「机器人未启动 / 等待连接」，**这个分支是对的**。

但独立模式（`standalone: true`）下，服务在跑、屏幕能抓、只是**读不到内容**
（游戏黑屏 / 加载 / 不在战斗），会走 `render(st)` 正常分支。
此时每个字段各自兜底成 `'—'`，**没有人从整体上判断"这一帧根本没有有效数据"**。

---

## 二、决策

### 2.1 加「空帧」判定，整块面板换文案

在 `render(st)` 开头判断这一帧是否"实质为空"：

```js
const noMe  = me.hp_pct == null && !me.name;
const noFoe = foe.hp_pct == null && !foe.name;
const noSkill = !(st.skills || []).some((s) => s && s.dmg != null);
```

三条全中 → 走 `renderNoData(st)`：保留系统栏（证明服务活着），
中间换成一句**说清原因**的说明，而不是 12 个破折号。

### 2.2 说明要区分三种情况

| 情况 | 判据 | 文案 |
|---|---|---|
| 服务在跑，抓不到画面 | `st.standalone && !st.system.detectors.bar` | 没找到对战画面 · 切到战斗后自动识别 |
| 服务在跑，画面是黑的 | `hp_pct` 全 null 但 `detectors.bar` 为 true | 等待画面 |
| 机器人没启动 | `/api/state` 为 null | 机器人未启动（**已有**） |

### 2.3 不删字段，只收起

不做"隐藏血条"这种结构性改动 —— 那会让"从空到有数据"时布局跳变。
做法是给 `.panel` 加 `data-empty="1"`，CSS 把两侧细节区折叠，
只留一行提示。数据回来时 `data-empty` 去掉，布局恢复。

## 三、实施

1. `ui/app.js`
   - `render(st)` 开头加 `isEmptyFrame()` 判定
   - 新增 `renderNoData(st)`，写清原因
   - 系统栏保持更新（证明服务活着）
2. `ui/style.css`
   - `.panel[data-empty="1"]` 折叠细节区
   - 空态提示条样式（和现有 `empty-skills` 一致）

   - 全空帧 -> 显示提示而不是 12 个破折号
   - 只有血条没有名字 -> **不**算空帧（血条是有效数据）

## 五、不做

- **不隐藏血条/技能区**（会造成布局跳变）
- **不改 `renderEmpty()`**（"机器人未启动"那条已经是对的）
- **不加动画过渡**（用户明确要求不能卡顿，折叠靠 CSS 立即生效）

## 六、实施记录（2026-11-21 21:30 完成）

### 6.1 空态效果

改前：12 个破折号 + 4 个「未知」
改后：

```
● 未在战斗  [独立]  T—
─────────────────────────────
        没有对战画面
   切到战斗界面后会自动识别
```

### 6.2 顺带修掉的四个死锁

这些是在实施过程中逐个实测出来的，不是预先计划的：

| # | 问题 | 表现 | 根因 |
|---|---|---|---|
| 1 | 前后端各一份测量逻辑 | 独立 webview 量 438，真实悬浮窗量 151 | Python 侧没同步 flexShrink 修复 |
| 2 | `p.children.forEach` | fit 静默失败，无任何日志 | HTMLCollection 没有 forEach |
| 3 | `pin size` 不同步 state | 窗口停在 620，面板只有 132 | `state["css_h"]` 还是旧值 |
| 4 | WebView2 缓存静态资源 | 改了代码完全没效果 | 没有缓存头 |

**第 4 条代价最大** —— 排查第 1、2 条时一直以为代码没生效，半小时后才发现是浏览器缓存。

### 6.3 关键根因：`position: fixed`

`body.embedded .overlay { position: fixed; inset: 0 }` 让 overlay
**完全脱离文档流**，尺寸由视口决定而非内容。panel 作为子元素
（`min-height:100%`）就永远等于视口高度。

这是"窗口矮 → 量出矮 → 判断不用改 → 永远矮"这个死锁的真正源头。
测量期间必须临时把 overlay 改成 `position: static`。

### 6.4 实机验证

空态 → 战斗的完整链路（2026-11-21 21:31 日志）：

```
fit: py=132 js={"e":"1","vh":134}   <- 空态，132
fit: css_h=134 -> SetWindowPos(720,268)

fit: py=362 js={"vh":364}           <- 有数据无技能，362
fit: css_h=364 -> SetWindowPos(720,728)

fit: py=435 js={"vh":437}           <- 完整战斗，435
fit: css_h=437 -> SetWindowPos(720,874)
```

截图确认：我方音速犬 100%、敌方里拉鳐 44%、克制关系「被克制 ×2.0」、
结论「2 回合击杀 · 2 回合被击杀 · 先手」、替补「剩 1/1」全部正常显示。

### 6.5 另一个坑：折叠态

排查过程中一直以为窗口卡住，实际是 `config/overlay.json` 里
`"folded": true` —— 悬浮窗处于**折叠态**，151 是正确高度。

折叠态只显示头部，这个行为本身没问题，但**日志里完全看不出是折叠态**，
导致排查方向全错。已在 `enter_embedded` 的日志里补上折叠态标记。
