# RocoAgent 项目总览

> 最后更新：2026-11-19 · 配套文档：`PVP_NOTES.md`（游戏机制）、`SYSTEM.md`（架构设计）

---

## 一、项目定位

用 BLE 硬件输入 + 纯视觉感知，自动打《洛克王国：世界》排位 PvP。
目标不是"能打"，而是**可解释、可验证、可持续改进**。

三条硬约束决定了全部技术选型：

```
① 游戏只认实体 HID 输入  → 必须用开发板，不能用 SendInput
② 状态只能靠截图感知      → 识别质量决定下限
③ 伤害是确定性的          → 可以精确建模，不需要概率近似
```

---

## 二、技术栈

| 层 | 用什么 | 为什么 |
|---|---|---|
| 输入 | ESP32-S3 + BLE HID + `espfast` 常连守护 | 外部设备，反作弊看不到 |
| 截图 | `mss`（`Screen` 封装） | 快（~10ms），支持窗口/客户区两套坐标 |
| 图像 | OpenCV（模板匹配 / 连通域 / 形态学） | 够用且可控 |
| OCR | RapidOCR（ONNX Runtime，CPU） | 离线、中文好、无需 GPU |
| 数据 | SQLite（`roco.sqlite3`） | 单文件、毫秒查询、可联表 |
| UI | tkinter（原生，`roco_gui.py`） | 30–50MB，不占资源 |
| 模拟器 | Python + NRC_AI 引擎（MIT） | 借架构不借数据 |
| 守护 | Windows 计划任务（每 2 分钟巡检） | 比常驻进程更抗崩溃 |

**Python 3.14**（venv: `CV_ESP_Game_1\.venv`）

**关键实现**：

- `Screen.sbox()/grab_s()`：所有锚点存**窗口相对坐标**，按分辨率等比缩放 → 换分辨率不错位
- `_click_target_ok()`：点击前 `WindowFromPoint` + `GetAncestor` 双重校验 → 不会点到别的窗口
- `_card_lit()`：用**名牌亮度**（245/196）判定卡是否可用，不用卡面美术
- `_plate_p75()`：名牌 p75，阈值 220

### 从调研里学到的三条

```
① 我们的"状态模型"是对的：roco-battle 独立实现出同样的
   4 点生命 / 印记 / 愿力 / 首领化 —— 可以互相校验

② 读屏路线有人走通过：RKHelper 同样从窗口读战斗信息。
   它强调"置信度 / 多分辨率 / 首次安装误报"，正是我们的痛点

③ 输入方案我们更安全：别人用 Interception 内核驱动或 pywin32，
   反作弊能看到；我们用外部 BLE 设备，不可检测
```
