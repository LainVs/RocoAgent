# 透明度热键档位与下限不一致

**版本**：`ui-m87`
**日期**：2026-11-21
**前置**：`ui-m86`

---

## 一、问题

两处配置互相矛盾：

```js
// ui/app.js:913
const ALPHA_MIN = 180;                 // 下限 180（ui-m67 定的）

// ui/app.js:922
slider.min = String(ALPHA_MIN);        // <input min="180">

// ui/app.js:1311
const ALPHAS = [100, 78, 55, 35, 20];  // 热键档位：最低 20
```

`Alt+A` 的处理：

```js
slider.value = next;                   // next 可能是 20
slider.dispatchEvent(new Event('input'));
```

**`<input type="range" min="180">` 会把 value 夹到 180** ——
所以设 55 / 35 / 20 全部变成 180。

### 1.1 实测表现

当前透明度 100% 时按 `Alt+A`：

| 按键 | 期望 | 实际 |
|---|---|---|
| 第 1 次 | 78% | 78% ✓ |
| 第 2 次 | 55% | **70.6%（= 180/255）** ✗ |
| 第 3 次 | 35% | **70.6%（不变）** ✗ |
| 第 4 次 | 20% | **70.6%（不变）** ✗ |
| 第 5 次 | 100% | 100% ✓ |

用户按 3 次，窗口纹丝不动 —— 看起来像"热键坏了"。

### 1.2 为什么下限是 180

`ui-m67` 定的（`docs/FRONTEND.md` §8.1.1 有实测表）：

```
整窗 alpha | 面板亮度 | 文字对比度 | 评价
255        | 246     | 7.2       | 优秀
230        | 224     | 6.6       | 优秀
200        | 198     | 5.8       | 优秀（推荐）
180        | 181     | 5.3       | 优秀（下限）
150        | 154     | 4.4       | 浅色背景下文字糊掉
```

**180 是有依据的**，不能为了迁就热键而降回去。

---

## 二、决策

### 2.1 热键档位改成与下限一致

```js
const ALPHAS = [100, 90, 78, 71];   // 100% -> 90% -> 78% -> 71%(=180/255)
```

等一下 —— 180/255 = **70.6%**，所以最低档应该是 180（不是 71%）。

直接用 **alpha 值（0~255）** 而不是百分比，避免换算误差：

```js
const ALPHA_STEPS = [255, 230, 200, 180];
```

对应显示：100% / 90% / 78% / 71%。

四档足够（用户实际只用"全亮"和"稍微淡一点"两种）。

### 2.2 加一条运行时断言

热键里所有档位必须 `>= ALPHA_MIN`，否则控制台报错。
这比注释更可靠 —— 以后有人加档位时会立刻发现。

```js
if (ALPHA_STEPS.some((v) => v < ALPHA_MIN)) {
  console.error('[hotkey] ALPHA_STEPS 有低于下限的档位', ALPHA_STEPS);
}
```

### 2.3 顺手修循环逻辑

现在的循环：

```js
let next = ALPHAS[0];
for (const v of ALPHAS) {
  if (v < cur) { next = v; break; }
}
```

`ALPHAS` 是**降序**，这个写法能工作，但依赖"必须降序"这个隐含前提。
改成显式排序 + 找下一个，更稳：

```js
const steps = [...ALPHA_STEPS].sort((a, b) => b - a);   // 降序
const next = steps.find((v) => v < cur) ?? steps[0];    // 到底回第一个
```

## 三、实施

1. `ui/app.js`
   - `ALPHAS = [100,78,55,35,20]` → `ALPHA_STEPS = [255,230,200,180]`
   - 循环逻辑改成显式降序 + `find`
   - 加下限断言
2. `src/test_ui.py` 加用例：
   - `ALPHA_STEPS` 全部 >= `ALPHA_MIN`
   - 按 `Alt+A` 四次，`slider.value` 依次是 255→230→200→180→255
   - 每次 `applyAlphaValue` 后 `--alpha` 的 CSS 值正确
3. 实机验证

---

## 四、验证

- `Alt+A` 四次循环，每次都有可见变化
- 最低档 = 180（= 下限），不再"卡住"
- `test_ui.py` 全过

---

## 五、不做

- **不降低 `ALPHA_MIN`**（180 有实测依据，见 §1.2）
- **不改滑块范围**（`min=180` 是对的）
- **不加新档位**（四档够用，多了反而难按）
