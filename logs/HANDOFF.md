## 一、启动方式（重要：进程被杀的坑）

**不要用 `Start-Process`。** 工具调用结束时，opencode 会连带杀掉子进程树，
bot 会在战斗中途消失，而且日志停在那一条，看起来像"卡住"。

用后台 shell 调用（harness 的 `background: true`），它活到 `--seconds` 到期：

```powershell
cd D:\Tools
C:\Users\Lenovo\Desktop\hardwork\CV_ESP_Game_1\.venv\Scripts\python.exe `
  -W ignore -u botsup.py --seconds 5400
```

`botsup.py` 是看门狗：robot.py 崩了会在 4 秒后自动重启，每次重启记到
`logs\supervisor_restarts.log`。今晚它已经救过两次（一次 AttributeError，
一次被手动 kill）。**直接跑 robot.py 也行，但没有自愈能力。**

已试过 `schtasks /create ... /sc once` + `/run`：**会起两个实例**
（venv 的 `python.exe` 是 shim，parent/child 两个 PID，看着像重复实例）。
用后台 shell 更干净。

### 防重复实例
`robot.lock` + `msvcrt.locking`（OS 级文件锁，进程死了自动释放）。
第二个实例会在**连蓝牙之前**退出，不会抢板子。已验证。
（早期用 pid 文件 + `os.kill(pid,0)` 判断存活，在 Windows 上不可靠，已弃用。）

### 日志
`robot.py` 自己往 `logs\bot_stdout.log` 追加（UTF-8），不依赖 shell 重定向
（PowerShell 里 `>>` 会写成 UTF-16，日志会变成 `0 3 : 1 9` 这种样子）。

## 二、每回合只有 15 秒，所以一切都必须是"一个进程 + 常连 BLE"

上一晚失败的**唯一**根因是延迟，不是策略：

| 做法 | 单次成本 |
|---|---|
| 每次调用 `ble.py` | ~4 秒（重新扫描+连接+断开）|
| 每次调用 `cap.py` | ~5 秒（`mss.mss()` 初始化 1.8s + 全屏 PNG 编码）|
| `robot.py` 常连 + 分区抓图 | 单次观测 **~75 ms** |

`mss.mss()` 的构造是 1.8 秒，一定要复用实例。全窗抓图 ~100ms，分区抓图 ~10ms。

## 四、界面判定：哪些信号可靠，哪些不可靠

### 可靠
* **倒计时数字**（顶部中央大白字）：战斗内我方格，白像素数 **0（动画中）vs 900~4300（可出招）**。
  门限 250。这是判断"轮到我"的首选信号，和卡面美术无关。
* **血条底板灰边**：`max-min < 20 && 70 < max < 125`，边缘两行占比 > 0.55。
  战斗 0.96+，菜单 <0.07。（原来的 `<14` 太紧，奶龙那种暖灰边会掉到 0.86 但边界行是 15-16）
* **卡片变暗 = 能量不足**。卡面（伤害胶囊上方那块）最大通道均值：
  可放 **148~159**，放不了 **56~88**。门限 105。
* **VS 过场**：左半窗 (150,250,300,300) 均值 ≈(35,135,171) 青，
  右半窗 (1900,250,300,300) ≈(196,96,22) 橙。全游戏没有第二处这么纯的双色分割。
  这是"绝对不许点击"的护栏。
* **伤害数字**：胶囊底色 (61,61,61) 反解 alpha → 模板匹配。
  `D:\Tools\digitread.py` 能读，但**必须注意**它当时是坏的：模板是 22×18，
  常量 `GW,GH` 是 14×18，`classify()` 直接抛 `matmul` 维度错。已改成按模板实际尺寸缩放。

### 不可靠 / 别再依赖
* **`find_pills` 的"精确等于 (61,61,61)±8"**：胶囊是半透明深色叠在卡面美术上，
  底色会随卡面漂移。**整场比赛读不到技能栏就是这么来的**——不是没显示，是检测掉了。
* **正数星标颜色**：能量低时星标变红/绿，会被 `find_pills` 当成"伤害胶囊"，
  于是 4 张卡读出 7-8 个胶囊。**不要按"星标颜色"判断能不能放**，用变暗判断。
* **★N 这个数字的含义**：同一只精灵同一技能，跨回合会变（★10 → ★5 → ★15），
  伤害数字不变。**不要当能量消耗去用**（按它算会误判），目前只当装饰。

## 五、出招逻辑（`robot.py::decide`）

```
1. 治疗：只有同时满足才治 —— 血量 < 40% 且 上回合掉过血 且 连续治疗 < 3 次
2. 在"可放（未变暗）"的伤害技能里，取非抵抗的最大伤害数字
3. 一个能放的都没有          → 按 F 聚能
4. 完全读不到                → 返回 None，调用方复用上一次成功的计划
                              （连续 3 次读不到才盲按 2 号位）
```

### 治疗循环这个坑（必读）

早期版本是「血量 ≤35% 就治疗」，但线上出现了**连续 8 回合治疗、
敌方始终 100%** 的两分钟空转（`logs/review_after_fix.md` 第 10-17 行）。

真凶不在阈值，在**计划缓存**：治疗被写进 `last_plan`，之后每个"读不到数字"的回合
都重放它，于是 24% 治好之后 hp 已经 54%、84%、96%、98% 了还在治。

三条修法：

1. **治疗永不进 `last_plan`**（这是根因）
2. 血量门槛 40%，且要求**上回合真的掉过血**（`prev_my_pct` 比较）
3. `heal_streak` 计数器，连续 3 次强制转攻击

回归测试：`python src\test_decide.py`（把复盘里那 8 个状态原样喂进 `decide()`）。
实测 278 次决策里最长连续治疗 **2 次**，治疗全部发生在 27-38% 血量。

### 奶龙的「储备金」
特性：每次聚能物攻 +50%。理论上正确打法是**聚能叠攻 → 物攻技能输出**。
目前没有验证过这个机制，所以**没有写死**；只在没能量时自然触发聚能。
要验证的话：从 `turns.jsonl` 里找「聚能」之后的回合，看伤害数字有没有涨
（同一个技能、同一个对手）。

治疗位识别：读不到中文技能名，所以用**"非伤害卡（dash）的槽位组合"**来认精灵：

```python
HEAL_BY_DASH = {(1, 3, 4): 4}   # 奶龙: 泥浆铠甲/电磁偏转/休息回复 -> 4 是休息回复
```

**注意**：只覆盖奶龙一只。其余 5 只没有治疗技能，暂时不需要。

## 六、节奏控制（防止把一回合按 30 次）

三层护栏，缺一不可：

1. **稳定读**：同一帧状态连续出现 ≥0.15s 才允许出招（半渲染帧会读出 `dmg 5` 这种鬼数字）。
2. **回合边界**：技能栏/倒计时消失 **>1.5s** 才算新回合（检测抖动 <1s）。
3. **硬下限**：两次按键间隔绝不小于 **1.2s**；同回合最多一次，8 秒无变化才重试。

实测效果：从「一回合按 32 次」降到「一回合 1~2 次」。

### 最重要的一条：**用技能栏出场，不要用倒计时出场**

倒计时数字比技能卡早出现几帧。早期版本用倒计时当"轮到我"的信号，
结果卡片还没画出来就去读数字 → 全读成 `--` → 只能盲按。
**改成一看到 `bar=True` 才出招**之后，感知失败率从 **88% 掉到 0%**（同一批对局实测）。

兜底：如果倒计时在跑但卡片 8 秒都没画出来，才盲按 2 号位。

### 耐心也是资源
15 秒的回合，出招只花 0.2 秒，所以**读不到数字时先等 2.5 秒再来一帧**，
比立刻盲按划算。`unreadable_since` 就是这个计时器。

## 六之二、非战斗画面的护栏（防止误点把对局关掉）

踩过的坑：战斗开场动画（顶部「特性：xxx」横幅、双方精灵登场）持续 10 秒以上，
期间血条 UI 还没画，`battle=False`，bot 会当成"结算页"去点中立点，**可能弃权**。

三层防误点：

1. **点「开始挑战」后静默 14 秒**（覆盖 VS 过场 + 开场动画）。
2. **VS 过场单独识别**（见第四节配色），识别到就绝对不点。
3. **推进点击只在对局结束后 120 秒内允许**；对局进行中一律不许点中立点。
4. 「退出」必须真的检测到白色按钮 blob，不靠"刚打完一局"推断。

## 六之二·补：底部那个按钮 = 一个东西，不是一个标签

**卡死 5 分钟的真凶**：卡在的不是结算页，是 **「确认首发」页**（开局前选首发）。
一直没点，因为代码只找「退出」，而且 ROI 比真实按钮高 300px。

更坑的是：那个页面和 VS 过场一样是青/橙双色分割，`has_vs_screen` 判定命中，
等于**主动拦住了唯一能开局的那一次点击**。

修法：不再认标签，认**位置 + 形状**。底部中央那一格会轮流出现：

| 页面 | 按钮 | 实测均值 |
|---|---|---|
| 开局前 | 确认首发 | (211,165,83) 暖黄 |
| 结算 | 退出 | (218,213,202) 近白 |

`find_action_button()` 在 `(1100,1480,400,150)` 里取「暖黄 ∪ 近白」的连通域，
挑最宽的圆角矩形（≥170×45），返回中心。两个按钮都点得到：

```
确认首发 -> (1736,1587)
退出     -> (1736,1571)
大厅/战斗/VS -> None
```

而且这个检查放在 `has_vs_screen` **之前** —— 按钮比配色更特异，不能再被护栏拦住。

### 卡死兜底（STUCK watchdog）
`last_progress_at` 在每局开始/结束、每次出招、每次点击时刷新。
超过 **60 秒**没有任何进度 → 打一条 `STUCK` 日志，找按钮点一次；
找不到按钮就中立点 + 按钮位各点一次。这样任何未识别页面都不会永久卡住。

### 看门狗也要看住自己
`botsup.py --seconds 5400` 到点会退出，**连带 robot 一起停**，
表现就是"5 分钟没有新对局"。长时间挂机要用 `--seconds 86400`。

## 六之三、强制换人（仍未解决 —— 需要人工实测一次）

精灵力竭后左侧出现 5 行替补列表。**四种输入全都无效**，而技能键明显能到达游戏
（同一时段技能在正常出手），所以不是焦点问题，是这个面板不吃这些键：

| 尝试 | 结果 |
|---|---|
| 数字键 N + Space（文档写法） | 无效，连按 12 次 |
| 只按数字键 N | 无效 |
| 鼠标点队员卡片 | 无效（卡片位置已精确量出） |
| 只按 Space | 无效 |
| E（底部写着「更换 E」） | 无效 |

**最后靠游戏自己的超时自动选人**，约 15-45 秒恢复。

### 面板识别（这个是有用的）
`find_switch_rows()` 靠左列 5 张**浅色圆角卡片底板**（~155×70，间距 ~150）识别，
并且**要求技能栏不在场**——因为技能卡的白名牌形状完全一样，会误判。
实测：真面板 5 行、死亡动画 0 行、普通战斗 0 行。

### 现在的策略（止损）
每种输入**只试一次**（E → Space → 点卡片+Space → 数字+Space），然后打一条
`waiting for auto-pick` 就安静等。不再像之前那样 30 秒里刷 12 次废输入。

实测效果：力竭后 15-45 秒自动恢复，**对局继续打下去**，不再整局白送。

## 七、当前状态 / 下一步

### 已验证
* 自动匹配 → 打完 → 点退出 → 回大厅 → 再匹配，闭环能跑（实测连续 3 局以上）。
* 真实对局里敌方血量在掉；击杀后对面换新宠会重新满血。
* 能量不足会自动按 F；残血会用 奶龙 4 号位「休息回复」自救
  （实测 24% → 54% → 84% → 96%）。
* 每局结束自动写 `logs\review_*.md`（决策日志版，比像素版有用）。
* 看门狗 `botsup.py` 已救过 3 次崩溃/被 kill。

### 当前关键指标
`review_turns.py` 的「感知失败率」= 读出伤害数字失败的回合占比。
* 修 `bar` 门控**前**：44% ~ 88%
* 修**后**：**35~40%**（好段落 0%）

### 认知：技能栏检测还有一个坑（已修）
`find_pills` 会漏掉**恰好带伤害数字的那张卡**——它的胶囊被卡面美术染了色，
连带着 4 个槽位只剩 3 个 dash，于是判定"读不到数字"，整回合盲按。
修法：`_fill_missing()` —— 用格点推算出缺失槽位的预期行，
在该行带状区域里**滑一个胶囊大小的窗口**，按"窗口内有多少像素接近 (61,61,61)"
打分（阈值 0.42）。不用连通域，因为卡片背后的场景（深色栏杆）也会连成一片。

回归测试：`python src\test_skillbar.py`（10 张真实帧，正例 3 张必须读出数字，
负例 7 张菜单/过场必须判 EMPTY）。

### 战斗/对局判定
* `battle` = 双方血条底板灰边都在（用于血量、力竭判断）
* **`live`（算一局开始）= `battle` 且（技能栏 或 倒计时）** —— 只有菜单碰巧有
  血条状边框时不会再被算成"一局 8 秒的对局"
* 一局结束 = `battle` 消失 **>6 秒**

**下一步优先修感知，不是修策略。** 失败回合里 bot 会复用上一条计划，
多数时候刚好是对的（2 号位是主力技能），所以还能打，但没有真正"看清局面"。

### 还没做
1. **换人策略**：现在强制换人固定 1 号位，且按键经常被吞（见 6-3）。
2. **属性克制**：只用了游戏给的伤害数字 + 是否抵抗，
   没接 `damage.py` 的克制表；对面 HUD 上其实有属性徽章（红/绿小圆标）可读。
3. **首领化（W→1→空格）**没用过。
4. **像素版复盘**：`rec3.py` 全窗 PNG 只能到 2.7 秒一帧，
   想按帧复盘要把录制改成 JPEG 或只存 HUD 区域。

### 已知遗留问题
* 偶尔还是会同一回合按两次（T8/T9、T16/T17），护栏已加强但没根治。
* 敌方换宠瞬间 `foe_pct` 会跳回 100%，被当成"没打中"，无伤大雅。
* `找开始挑战` 和 `找退出` 都是**单点坐标点击**，窗口换分辨率就会失效，
  需要重新按 blob 检测结果算坐标（函数已经在算，只是点击用的是常量）。
