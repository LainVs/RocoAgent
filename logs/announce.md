# 技能播报（出招提示条）定位与读取

扫描素材：`logs/frames/`（240 张，00:54–01:29）+ `logs/frames2/`（抽 1/4，226 张，02:50–03:21），
均为 2586×1671、约 0.4 s 一帧。逐帧跑过 **467 帧**，命中 **26 条播报**。

> 说明：`logs/frames2/` 是滚动覆盖的环形目录（实测前后两次列目录，文件名区间已经从 01:21 变成 03:30），
> 开工时那批全是「队伍编辑」界面，真正的战斗帧在 `logs/frames/` 里；换到新一批后 frames2 也有战斗。

---

## 一、播报的精确矩形

播报是**贴右屏幕边缘**的一条半透明黑底横幅，单行，右对齐，文字由两段不同颜色组成。

| 部位 | 坐标（2586×1671 基准） | 说明 |
|---|---|---|
| 文字墨迹（含 ★ 与 ！） | `x 1775 – 2340`，`y 262 – 316` | 高约 54 px，实测 10 条干净帧的并集 |
| 深色底条 | `x 1745 – 2586`，`y 258 – 330` | 左边缘随文字长度浮动（最长约 1745，最短的「特性：」约 2065），右侧顶到屏幕边 |
| **推荐裁剪矩形** | **`(1700, 250) – (2430, 342)`** | 690×92，留足上下左右余量，直接喂 OCR |

文字基线固定，垂直位置不随文字长度变化；**只有左边缘会动**。

> 之前试的 y 40–160（倒计时）、y 360–540（场景）都不对。y 340–390 那条统计峰值是战斗场景里的天空/建筑高光，不是文字。

---

## 二、播报的文字结构（关键）

一行里其实混了两种颜色，这是之前 OCR 只读出一半的原因：

| 颜色 | 内容 | 例子 |
|---|---|---|
| 白色 | `<角色名>` + `使出了` / `召唤了` / `特性：` | `骑士海豹船长 使出了` · `迷人的张三疯召唤了` |
| 金色 | `★`（星形图标，OCR 永远读不出） | —— |
| 白色 | 技能等级数字 | `4` |
| 彩色 | `<技能名>` / `<召唤物>` / `<特性名>` | `听桥` · `完美的冥古龙` · `恶龙的奢望` |

注意：技能名**不一定橙色**，会随属性变色（火/普通=橙，草/风=绿，实测 `蓄能轰击` 是绿色）。
所以不能只过滤橙色，要按「亮且高饱和」取色。

## 三、识别方法（<ROCO_TOOLS>\announce.py）

1. 用文字行的上下留白行（y 263–272 / 315–326）判定横幅左边缘——横幅内是均匀暗色，外面是场景，从右往左扫即可。
2. 取「白字」+「亮彩色字」两个掩膜并集，二值化成黑字白底（**不能直接喂彩图**，彩图 Windows OCR 会整段丢掉彩色部分）。
3. 行内去噪（只留文字行上的连通块）+ 丢弃过大色块（横幅边、场景）。
4. 同时出 2 种裁剪起点 × 2 种缩放（3×/4×）共 4 张图，全部 OCR，按「含关键词 + 长度」选最优——单尺度会偶发整段截断。
5. 文本后处理：去首部杂字、把 `使出了` 后的杂字+数字还原成 `★数字`。

## 五、准确率

| 指标 | 数值 |
|---|---|
| 定位召回（有播报的帧被找到） | **26 / 26 = 100%** |
| 误报（没播报却读出字） | **0 / 441 帧** |
| 行级完全正确 | **22 / 26 = 85%**（frames: 10/10，frames2: 12/16） |
| 字符级正确率 | **约 98%**（373 字，8 处错误） |
| 单帧耗时 | 复用常驻进程 **约 1.6 s**；冷启动单张约 10 s |

剩下的 4 条都只差 1–4 个字，且原因单一：

1. **横幅淡入帧**（`031230`）：整行是半透明灰字，底色对比不足 → 尾部丢失。这类帧是过渡帧，同一句话在 0.4 s 内的相邻帧会变成实心字，重采即可。
2. **字形被拆**（`恶魔狼` → `恶魔犭良`）：OCR 把左右结构汉字拆成两个部首，属字体/字号问题。
3. **绿色技能名漏字**（`蓄能轰击` → `蓄能击`）：彩色行本身对比低于白字，偶发漏笔画。
4. 尾部/首部杂字（`0`、`区`、`孬`）：★ 图标和横幅边缘被误当字符，已在后处理里尽量剥离。

**结论：不是"位置不对"的问题。** 位置一旦定在 `(1700,250)-(2430,342)` 就是稳的；出错全在**颜色/对比**上——单色 OCR 会整段丢掉彩色技能名，必须拆色 + 二值化；再叠加半透明淡入帧的对比不足。字体本身（思源类黑体、约 28 px 字高）对 Windows OCR 基本友好，只有拆字（犭良）和绿字漏笔画这两类残余。

## 六、工具有用法

```powershell
# 单张：打印播报（无播报输出空）
python <ROCO_TOOLS>\announce.py .\logs\frames2\025114_0519.png

# 整个目录（推荐，启动开销摊薄，241 张约 3 分钟）
python <ROCO_TOOLS>\announce.py .\logs\frames2 --out result.tsv
```

Python 里实时用，请复用常驻进程，否则每帧要付 ~9 s 的 PowerShell 冷启动：

```python
import sys; sys.path.insert(0, r'<ROCO_TOOLS>')
import announce
worker = announce._Ocr()                       # 只启动一次，约 2 s
txt = announce.read_announce(shot_path, ocr=worker)   # 之后每帧约 1.6 s
```

## 七、采样注意

0.4 s 一帧的素材里，**每条播报几乎只出现在 1 帧**（`frames/` 78 帧战斗共 10 条，两两互不相同，没有连续重复）。
即播报实际显示时长 ≤ 0.8 s。想不漏播报，采样间隔必须 ≤ 0.4 s；一旦掉帧就会整条丢失——这是当前最大的漏检风险，比 OCR 误差重要得多。
